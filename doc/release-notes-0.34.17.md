# 0.34.17

`main` at 0.34.16 is the parent. This version does not change consensus, script, issuance, or MatMul acceptance. `automatic_spend_atoms` remains `"0"`.

A live SwapNet route is no longer replaced when a different peer replays a valid packet or advertisement. The first live next hop stays until it expires. `getswapwalletinfo` now requires the owner. It returns the node identity and foreign-chain accounts.

A maker checks proposal deadlines after it has read both chain clocks. The time captured when the proposal arrives is still what the quote is checked against. A remote endpoint no longer makes that deadline check fail with `STALE_CHAIN`.

`lab.deployment_observe` no longer moves a rollout plan that is `PAUSED`. A snapshot import checks the model bytes named by each piece before the import is installed.

Claim and refund keys remain fields of the signed agreement, so they are still created before that signature. No trade-size minimum beyond a positive amount was added. The Windows foreign-vault file layout is unchanged.

The Windows unit fixture no longer includes `<unistd.h>` or the Unix-socket feed case. The other bridge cases stay compiled. `doc/modelnet/recovery.md` now describes keeping an independent copy of a retained model export and restoring it with `importmodel`. That is not a rebuild of the catalog from cloud objects alone.

The SwapNetHTLC artifact in this tree is open. Under solc 0.8.24, EVM version shanghai, with the optimizer at 200 runs and no metadata hash, its runtime keccak256 is `a06e30bad714ff02db5a2401a898bd7194d1c475b61bdab312ae194b1509e45d` and its creation-code keccak256 is `401e81e4ab795f39e48b76bda608771e10078e23cfc1d807983b05ee3da97cde`. Cancun produces the same bytecode. Paris does not. `foundry.toml` pins shanghai. A matching runtime hash is not enough. Different init code can write a lock into storage while the contract is being created and then return this runtime, so two nodes can pin the same address and the same runtime hash with nothing behind the lock. Deploying this creation code with CREATE2 through the permissionless proxy `0x4e59b44847b379578588920cA78FbF26c0B4956C` and salt keccak256(`BTX/SWAPNET/HTLC/1`) yields `0x944C528F2e206a93CEb32B4723cd25DAa8f303EF`. That address is a recommendation, not an appointed deployment. The proxy has no admin key, and this release does not send the transaction. The address is fixed by the proxy, the salt, and the creation code, so independent owners who pin it are on the same deployment. A node still requires its owner to set both the address and the runtime hash. An owner who pins a different address has to check that the creation input is this creation code.

An incomplete admitted catalog entry can be filled by ordinary `getmodel` from configured cloud storage. That path does not require `direct_seed`. It does not rebuild a catalog from bucket objects alone. `direct_seed` and `direct_seed_fetch` remain a separate fetch.

The Linux archives carry libevent, libsqlite3, libzmq, libgomp, and the libraries those need. A base image does not have to install them. libc and libstdc++ stay on the host. The NVIDIA driver library is not in the archive. Every bundled library is within GLIBC 2.38. The wrappers use `awk` for that check. Ubuntu 22.04, Debian 12, and EL9 are below this floor and need a source build.

The published v0.34.16 CUDA archive was replaced after its first upload so it carries those same host libraries. The current asset on the v0.34.16 release is `btx-0.34.16-x86_64-linux-gnu-cuda13.tar.gz`, 455,173,097 bytes, SHA256 `a29202a919039c50547c90a19bb48ddc9e434c9365793131d7bda3155b3822dd`. That is the line in the release `SHA256SUMS`. An earlier brief named `18c860c02e3a3f79851dc7caabcdc5dfc756fd062b4d077180c45776dc0472a7`. That digest is the previous upload, not the file on the release now. `SHA256SUMS` is unsigned. This note does not say the archive was run.

SwapNet starts its embedded Python with an isolated configuration. It does not read `PYTHONPATH` or the user site directory. A Linux release archive points that interpreter at the Python shipped under `lib/`. A Windows build uses the Python prefix selected at configure time, and `cryptography` is loaded from that prefix's site-packages. That install is part of the node.

The external-sign, bounty, and model-plane documents now say what this build returns. Reachability stays `UNKNOWN`. There is no compiled-in model hub and no compiled-in DNS seed. LAN discovery stays on when the helper listens and neither `-proxy` nor `-connect` is set. The peers that tick already dials, including those LAN hints, are asked for their local search index with the existing `ext/search` request, and a verified record is stored. `searchmodels`, `searchbounties`, and `getmodelfeed` use that same peer list. `getmodelavailability`, directory cards, and search cards use the catalog's piece count when this node has the file list, and otherwise follow the documented fallback: no observation is `UNKNOWN`, and an observation with an unknown piece count is `HIGH`. A search record may still name a publisher that did not sign it. A pending deposit that leaves the mempool still becomes `UNKNOWN` without a new event.

Atlas can read the SwapNet status this node already exposes, and the model directory, availability, browse, and LAN discovery calls. A quote, accept, refund, fee bump, mandate, or recovery export is prepared for native review. Atlas does not spend, and it does not add a hub. The desktop shell registers `atlas_take_swapnet_invites`, which the SwapNet page already calls for a `btx://swapnet/v1/` link given at launch. Inspecting that link does not connect or spend.

A native BTX `getmempoolentry` or `getrawtransaction` that reports the transaction is absent is no longer wrapped as a generic `NATIVE_RPC`. `has_transaction` can tell that absence from a failed node call, so a prepared funding transaction is broadcast. A txindex that is still syncing stays a failure.

An empty RC proof read no longer calls `memcpy` with a null source. The length is already zero, so nothing is copied. Acceptance of a non-empty proof is unchanged.

Helper stores keep a bound on idempotency keys, plans, events, watches, drafts, challenges, pledges, and caller strings, and they keep the newest or still-valid entries. A commitment is revealed once. An award requires the revealed submission to still be there. A failed retrieve cancellation is reported so it can be retried. A subscription mandate refuses a restriction of the wrong type. A helper JSON store that cannot be read is left in place. A prefix Python install includes third-party packages that sit in `site-packages` or `dist-packages` under the standard library.

MSVC can reduce a negative matmul accumulator. `Signed128` converts to `Unsigned128` by copying the bits, which is what `static_cast` of the native 128-bit type already did. GCC and Clang still use that native type. MSVC also reads AVX state through its CPU intrinsics, leaves the CUDA row-leaf hook unset, uses a signed OpenMP loop index, and tests a 128-bit shift against zero. The GCC and Clang shift, the weak hook, and the values those loops write are unchanged. MSVC itself was not rerun. A shielded-wallet scan no longer captures a structured binding inside a lambda, so Clang with OpenMP can compile it. The comparison is unchanged. The same capture is removed from the terminal-fold alias constraints and from one Split-RAP test lambda. The column indexes and the relation those lambdas read are unchanged.

Configure requires Python 3.11 or newer, its headers, and `cryptography`, because `btxd` links `libpython`. The dependency list matches that. Ubuntu 22.04's Python 3.10 is not enough. The Windows build script accepts `-WithoutModelNet` when OpenSSL 3.5 is not available. The packaged library runpath is one `$ORIGIN/../lib`. A backslash before that dollar made CMake 3.22's Makefile generator write `$$ORIGIN`, which the loader does not use. Ninja and Unix Makefiles both record `$ORIGIN/../lib` with CMake 4.3. CMake 3.22 itself was not rerun.

A closed local SwapNet RPC port is still a refusal, not a timeout. The Windows check waits long enough for that platform to report the refusal. The product timeout stays 10 seconds.

An outbound peer that can serve blocks and stays behind this node's tip is eligible for chain-sync eviction again. The header-height gate is unchanged, and this does not change which block is valid. Discouragement disconnects the misbehaving connection. An overlong Bech32 string is still invalid; the error names the first position past the limit. Address selection draws uniformly inside a bucket. Mempool memory usage counts unbroadcast txids. A package child that is already in the mempool leaves the orphan set. A failed JSON parse leaves a null value. `setmodelalias` and `removemodelalias` save the search index before they publish it. Mesh export and channel staging read past the first 1024 stored records of that kind. A revoked evaluator `FAIL` still blocks admission. A rollback under a required mesh still uses the coverage check this tree already had.

A failed model transfer gives its credit back once. A piece that arrives is recorded on the request still in flight. An S3 object without Content-Length that runs past the requested range is refused. An S3 TLS read or write that hits the socket timeout ends. A short Neuron Lab confirmation still names the signed operators, their count, and their digest. An empty or unexpected Ethereum transaction lookup is an error. JSON null is still absence.

On macOS the capability and model helper sockets use a path that fits in `sun_path`. An AUTO storage profile is checked against the quota that current free space produces.

SwapNet schema setup no longer steps a null SQLite statement or rewrites the journal version on a database that is already current, so a start does not log `SQLITE_MISUSE` or `SQLITE_SCHEMA`. SwapNet starts with the node so the people running this build dogfood discovery and taker participation. The default mode on a new journal is `taker`. A journal carried over from v0.34.16 with no saved mode also comes back as `taker`. Publishing markets then needs `setswapmode` with mode `maker`, or `-swapnetmode=maker`. A saved owner choice of `maker` or `observe` is kept across restart. `-swapnetmode` is the explicit override. `-swapnet=0` does not start the engine. A SwapNet start that fails stops the node. Recovery of existing obligations is `-swapnetmode=recovery`, which refuses a switch to maker or taker until restart. Taker mode can request a quote. It does not spend. Maker, a public firm slot, a quote, a confirmation, and an invitation connection still require native review and an owner mandate. A firm offer is a local capacity reservation, not escrow or proof of solvency. An invitation does not grant wallet authority. ModelNet and SwapNet share a rate-limited control process and keep separate custody. `automatic_spend_atoms` remains `0`. This note does not record a funded BTX/BTC or BTX/ETH settlement.

An unset `-reorgpolicy` stays legacy. Pool, exchange, and swap-maker nodes should set `-reorgpolicy=bounded`.

A mature local refund still runs when only the other leg conflicts. A short leg must have time left for its own confirmations before funding. Broadcast inquiries do not crowd out a directed packet. A new EVM trade requires the pinned creation code. An instant wBTX limit or compliance-hook change stays the intended admin action; the external timelock is the delay. A wallet-notify replacement is copied literally. A manifest path longer than 240 characters is refused before the pattern is applied. Encrypting a wallet keeps the existing P2MR seed. A shielded bundle counts toward memory limits. An owner archive cannot ask for more derivation work than this release writes. A paused peer is not read on the select path. A header presync keeps its index window through the epoch-A re-anchor, and the window still has a fixed bound. An invalid shielded proof discourages the peer that sent it. A lab model pulled over its `max_bytes` limit is not kept. The nearly-funded feed orders by the amount still left. A sync from genesis still stops at the existing shielded velocity check. A node that wants the tip starts from a snapshot. The published CUDA build needs compute capability 8.0 or newer. An older card keeps mining on the CPU.
