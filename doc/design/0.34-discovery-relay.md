## 1. Why public seeds were the wrong oracle

Today DNS/`addnode` targets (`node.btx.dev`, `node.btxchain.org`,
`node.btx.tools`, and the IPs in the archival bootstrap runbook) are treated
as chain oracles:

- Clients IBD from them (`NODE_NETWORK`).
- Trusted public seeds request `GETMMATTEST` from GPU attestors so they can
  skip ExactReplay on pin quorum.
- `getbestblockhash` / headers from those hosts are treated as “the
  network.”

That **centralizes** MatMul authority on a handful of machines and **puts
load on the GPU attestors** every time a public seed
catches up. A stolen seed, or a seed that is merely overloaded, looks like
the chain.

The chain is not “whatever the seed IP says.” GPU nodes ExactReplay. Archives
that opt into trusted-mirror follow an attested tip via **their** pin. Public
introduction hosts only point at other nodes.

## 2. Roles after this change

```
GPU attestors (consensus + signer WIF)
        |  MMATTEST / GETMMATTEST (operator-chosen pin)
        v
Trusted CPU archives (light clients of their local pin)
        |  ADDR of miners, archives, relays
        v
Discovery relays (-matmulvalidation=relay)   ← public DNS / addnode
        |  ADDR only (NODE_MATMUL_DISCOVERY, no NODE_NETWORK)
        v
New miners / full nodes / light clients
```

| Role | Flag | Authority | GETMMATTEST | Public DNS/addnode |
|---|---|---|---|---|
| GPU miner / attestor | `consensus` (+ optional signer) | This node ExactReplays | Serve optional; **never publish the signer IP** | No |
| CPU archive | `trusted` + pin M≥2 | Pin replaces ExactReplay *for this node* | Cache-and-forward | No (not as a seed oracle) |
| **Discovery relay** | `relay` | **None** | **Neither request nor serve** | **Yes** — this is the public seed layer |
| Economic / SPV | lab only | Skip MatMul | Forbidden on mainnet | No |

“Current network as reported to the archives from the GPU nodes they
follow” is the **operator’s pin / attested tip**, not a new gossip-majority
oracle and not `getbestblockhash` on a public seed. Relays learn peer
addresses from the live mesh (archives and public miners they are addnode’d
to). They do not steer `FindMostWorkChain`. Open keys and peer counts stay
Sybil; they are not wired in.

## 3. What `-matmulvalidation=relay` enforces

Fail-closed on start:

- Mainnet **allows** `relay` (named exception). Economic/SPV stay forbidden.
- No `-matmultrustedpubkey`, signer WIF, `-matmulattestationserve=1`,
  blocklist, or open attestors.
- `-disablewallet=1` required.
- `getblocktemplate` refused.
- Advertises `NODE_MATMUL_DISCOVERY`. Does **not** advertise
  `NODE_NETWORK`, `NODE_NETWORK_LIMITED`, `NODE_MATMUL_CONSENSUS`,
  `NODE_MATMUL_TRUSTED_MIRROR`, or `NODE_MATMUL_ATTESTATION_ARCHIVE`.
- Does not request `GETMMATTEST`.
- Does not download block bodies (`FindNextBlocksToDownload` returns).
- `FindMostWorkChain` stays on the loaded tip; `ConnectTip` refuses to
  activate new blocks (does not invalidate them).
  - ADDR_FETCH / `-seednode` keeps a peer that advertises
    `NODE_MATMUL_DISCOVERY` even without `NODE_NETWORK`. Full outbound
    still requires `NODE_NETWORK|NODE_WITNESS`. DISCOVERY is **not** in
    `GetDesirableServiceFlags`.
  - ADDR / GETADDR (the actual peer-node function):
  - Learn addresses only from outbound, `-addnode`/manual, or DNS
    addr-fetch peers (archives reporting the GPU-followed mesh). Random
    inbound ADDR does not fill AddrMan.
  - Raise a “recent network” watermark from outbound/manual `NODE_NETWORK`
    peers that advertise `NODE_MATMUL_CONSENSUS`,
    `NODE_MATMUL_ATTESTATION_ARCHIVE`, or `NODE_MATMUL_TRUSTED_MIRROR`
    (their VERSION height). Public miners count: the relay must not depend
    on CPU archives as the only recent-network oracle. After the first
    sample, later raises must stay within 72 height. That is introduction
    policy. It is **not** `HasQuorum` and does **not** steer
    `FindMostWorkChain`.
  - GETADDR hides services that look like a serving GPU attestor
    (`NODE_MATMUL_CONSENSUS` ∧ `NODE_MATMUL_ATTESTATION_ARCHIVE`) so
    GPU attestor IPs are not gossiped. `-discoveryrelayhideaddr=<ip>`
    also hides serve=0 attestors that advertise CONSENSUS only. Relays
    InitError if `-addnode`/`-connect`/`-seednode` targets a hidden IP.
  - GETADDR prefers currently connected outbound/manual peers whose
    VERSION height is within 72 of that watermark.
  - Does not serve or ingest block bodies, compact blocks, headers,
    GETHEADERS (empty response), GETBLOCKS, GETDATA, GETRCCARRIER, or
    GETSHIELDEDDATA. Converted archival datadirs stay ADDR-only.
  - SoftSets `-blocksonly=1`, `-whitelistrelay=0`, and a small mempool.
  - RPC: `getbestblockhash`, `getblockcount`, `getblockfrompeer`,
    `submitblock`, `loadtxoutset`, `loadtxoutsetattested`, and
    `offerattestedutxosnapshot` are refused. `getblockchaininfo` /
    `getnetworkinfo` remain for monitoring (`chain_oracle=false`,
    `discovery_archive_reported_height`). `getnodeaddresses` applies the
    same hide filter.

RPC: `discovery_relay=true`, `chain_oracle=false`,
`getfinalityinfo.warnings` includes `not_a_chain_oracle`.
`-matmulrcprovisionalrelay` is a different flag (provisional RC compact
block relay) and is not this node class.

This is **not** economic mode with a new name. Economic still connects
unverified Profile-1 bodies as valid. A relay never becomes a silent
chain oracle.

## 4. Operator conversion

Public DNS/addnode hosts (`node.btx.dev` and siblings):

```
./contrib/devtools/gen-btx-node-conf.sh discovery
```

or:

```
matmulvalidation=relay
disablewallet=1
# no matmultrustedpubkey, no signer, no attestationserve
```

GPU attestors:

- Stay `-matmulvalidation=consensus` with the signer WIF on the attestor
  process only.
- `-discover=0`. Never in DNS, `addnode`, or `vSeeds`.
- Prefer `-matmulattestationserve=0` on the operator’s own signer; archives
  cache-serve `GETMMATTEST`.

Archives that remain CPU: opt into `trusted` with a pin **they** choose
(prefer M≥2 independent signers they can reach). They are the IBD/body
source and the attestation cache. They learn the chain from GPU attestors
they pinned, not from relays. The network designates no canonical
attestors.

New miners: `addnode` the **relay** DNS names to learn peers, then IBD from
`NODE_NETWORK` archives/miners the relay introduced. Default
`-matmulvalidation=consensus` (no pin). If you opt into trusted-mirror,
confirm **your** pin on **local** RPC after joining; P2P does not push keys.

## 5. What this does not do

- Does not reseal EncDr / ASERT / F / header-PoW.
- Does not put open keys into `HasQuorum`.
- Does not auto-51% from gossip or peer counts.
- Does not make a relay’s header tree the network’s chain.
- Does not take down a running GPU attestor process.
- Does not bump `CLIENT_VERSION` or push.
- Does not add invented seed IPs or put `NODE_MATMUL_DISCOVERY` into
  `SeedsServiceFlags()` (DNS x-subdomain must still find `NODE_NETWORK`
  archives; relays are the empty-x ADDR_FETCH fallback).

## 6. Day-one addresses (operator, not this binary)

Discovery relays do not invent bootstrap addresses. Fresh-node addrman is
still only as diverse as DNS seeds plus `chainparamsseeds.h`. Operator
checklist before calling 0.34 a network:

- 6–8 seed operators, not all the same people who sign releases, not all
  one ASN.
- Each seeder returns many A and AAAA records, not one.
- Regenerate `src/chainparamsseeds.h` from a crawl (`contrib/seeds`,
  Bitcoin PR #18506 process) so the fixed list is a real fallback.
- DNSSEC on seed zones is integrity, not a substitute for seeder
  diversity.
- `-asmap` once the reachable set spans more than one ASN. No map ships
  in the tree (same as Bitcoin Core); a stale map can make eclipse
  easier.
