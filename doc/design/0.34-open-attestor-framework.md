# 0.34 open attestor framework — local design study

Status: **PR branch** `pr/0.34-open-attestor-framework`. Not consensus. Not a
release cut (`CLIENT_VERSION` stays 0.33.4.x). Not a merge to main. Pin quorum
for CPU archives is unchanged: `-matmultrustedpubkey` / `-matmultrustedthreshold`
remain sufficient. Open attestors are an additional admission path.

Epoch A is live: Profile 1 ExactReplay is consensus authority (mainnet height
185000). Attestations are a **sidecar**. 0.34 must keep that split. Epochs
B–D (durable proof, then proof authority) are separately reviewed heights and
are how phones eventually stop needing attestors at all.

## 1. One-line rule

**Any qualified GPU may *say* it ExactReplay’d a header. No set of those
sayings may *be* the proof of work, the light-client security model, or a
reason to spend miner GPU on history.**

If 0.34 violates that, “open attestors” is just a larger Liquid federation.

## 2. What exists today (code)

### 2.1 Statement (reusable)

`ExactReplayStatement` v2 in `src/matmul/trusted_exact_replay_attestation.h`:

- `chain_id` (genesis), `block_hash`, `block_height`, MatMul v4, Profile 1
- `replay_authority_context` (schema 4) — fingerprints consensus schedule and
  the ExactReplay predicate, **not** the signer set
- Domain: `BTX_TRUSTED_EXACT_REPLAY_ATTESTATION_V2`
- Compressed secp256k1 ECDSA, strict DER / low-S
- Explicit comment: *not consensus proofs, do not change block hash*

`UntrustedSigner` is the closed-membership gate: a valid signature from a key
not in the local pin is discarded. Relayers are not punished for carrying it.

`replay_authority_context` is `ComputeMatMulReplayAuthorityContext` in
`src/node/blockstorage.cpp` (`SCHEMA_VERSION` 4). Membership is hashed
separately as `AuthorityNamespace` in
`src/node/matmul_trusted_attestations.cpp` (`chain_id`, context, M, ordered
pubs) for the LevelDB prefix. Rotate the pin and old records become
prior-authority, not a fork of the predicate.

### 2.2 Roles

| Role | MatMul check | Signs? | Serves GETMMATTEST? |
|---|---|---|---|
| Consensus, no pin | local ExactReplay | no | no |
| Consensus + pin | ExactReplay; pin quorum never skips GPU | no | optional cache-forward |
| Consensus + WIF | ExactReplay then `SignAuthoritative` on connected blocks | yes | live window + cached catch-up |
| Trusted mirror | **quorum replaces ExactReplay** | never | cache-and-forward |

P2P: `GETMMATTEST` / `MMATTEST` (`src/protocol.h`). Payload is policy trust
data. Service bits `NODE_MATMUL_CONSENSUS`, `NODE_MATMUL_TRUSTED_MIRROR`,
`NODE_MATMUL_ATTESTATION_ARCHIVE` are unauthenticated VERSION ads.

### 2.3 Admission is local config only

Keys enter only via:

- `-matmultrustedpubkey` (repeat, distinct)
- `-matmultrustedthreshold`
- `-matmulattestationsignerkeyfile` (consensus mode only; pubkey merged at
  Finalize)

README / faststart / `gen-btx-node-conf.sh` publish an **out-of-band pin**.
P2P seed connect does **not** push keys. `getmatmultrustedstatus` confirms
*your* pin after join.

There is no on-chain registry, no P2P “here is a new attestor pubkey”
message that mutates `trusted_signers`, and no VRF/stake sortition.

### 2.4 DoS surfaces that must survive openness

Live signers:

- `SIGNER_GETMMATTEST_SERVE_WINDOW = 16`
- `SIGNER_GETMMATTEST_CACHED_CATCHUP_WINDOW = 256` (archive/mirror catch-up
  peers only; `SignAuthoritative`, never ExactReplay regen)
- hammer-ban after 32 ignored GETMMATTEST
- historical reverify budget: burst 2, refill 30s, queue 4, inflight 1

Caught-up archives serve historical GETMMATTEST from cache. IBD scans of a
signer are ignored on purpose.

`HeightOccupied`: a local signer mints at most one hash per height. P2P
`Add()` can still store a second hash from the *same* key (recovery). OPEN
membership needs a **network-visible** equivocation object (two statements,
same key, same height, two hashes).

### 2.5 Combined miner + signer

Auto-sign after ExactReplay (`validation.cpp` ConnectTip path). If that
process ExactReplays a losing twin first, `HeightOccupied` blocks signing
the winner. Do not collocate the attestation WIF with public mining. OPEN
keys make this worse if “anyone can join” includes public miners.

### 2.6 Fork choice vs validity (the trap)

Consensus nodes **without** a pin ignore attestations as validity and as
fork choice.

Consensus nodes **with** a pin still ExactReplay. The pin is telemetry
(GETMMATTEST serve, directory) and, if the node also has a local WIF,
lost-twin recovery via `FindUniqueCompetingAttestedIndex`. Pin quorum does
**not** steer `FindMostWorkChain` or getblocktemplate on consensus. A
stolen pin key cannot skip GPU or mint `nAuthenticatedChainWork` on a
consensus miner.

Trusted mode: quorum **replaces** ExactReplay and **does** steer FMWC/GBT
(CPU-archive weak subjectivity). Mainnet 1-of-1 is a warning: that key is
that node’s MatMul PoW.

Opening the set without changing *what a quorum is allowed to mean* is a
larger federation, not decentralization.

## 3. The decentralization paradox

Three goals that cannot all be true in Epoch A:

1. CPU VPS public seeds stay at the MatMul tip without a GPU.
2. Anyone with a GPU can become an attestor without a ceremony.
3. Stolen attestor keys cannot mint fake work for those CPU seeds.

Today we take (1) and refuse (2): a static pin. Liquid-shaped.

Maximum decentralization of **validation** is Phase 3 of the GPU-transition
doc: every public full node ExactReplays. CPU boxes become light clients.
Attestation is optional telemetry.

Maximum decentralization of **attestation** in Epoch A is: anyone may gossip
a v2 statement; CPU clients treat it as a rumor; watchtowers refute;
compiled pins bury history. CPU seeds then cannot independently stay at tip
unless they pick a pin (weak subjectivity) or wait for a GPU they control.

0.34 should **open who may speak**, keep **client-local who may rule**, and
add **refutation + logs + pins** so a stolen WIF is not a fake miner for
long.

Succinct-proof Epoch C is when (1)+(2)+(3) become compatible: the phone
verifies a proof, not a key.

## 4. What other systems teach (and what not to copy)

### 4.1 Do not put attestors into the block

| System | Why it is the wrong 0.34 consensus object |
|---|---|
| Liquid Strong Federation | Functionary signatures *are* the block. Stolen M keys = fake chain. [strong-federations.pdf](https://blockstream.com/strong-federations.pdf) |
| Ethereum Altair sync committees | 512 rotating validators, BLS aggregate **in the beacon block**. Prestwich: members are rewarded for valid attestations and **not slashed for invalid ones**; dominant strategy is sign everything. [consensus-specs light-client](https://github.com/ethereum/consensus-specs/blob/dev/specs/altair/light-client/sync-protocol.md) · [Altair is no Light Client](https://prestwich.substack.com/p/altair) · stagnant [EIP-7657](https://eips.ethereum.org/EIPS/eip-7657) |
| GRANDPA as required finality | 2/3 prefix votes become fork choice. [arXiv:2007.01560](https://arxiv.org/abs/2007.01560) |

BEEFY’s *shape* (sidecar signatures over an MMR of already-true facts) is
usable. GRANDPA-as-must-extend is not.

### 4.2 Header-sampling light clients do not replace ExactReplay

FlyClient ([eprint 2019/226](https://eprint.iacr.org/2019/226)) and NIPoPoW
([eprint 2017/963](https://eprint.iacr.org/2017/963)) sample **header PoW**.
A BTX header `matmul_digest` is not a hash of the header; real work is
Profile 1 ExactReplay of the body. Sampling headers samples claimed work.
These belong after Epoch C, when a succinct proof is in/near the header.

Bitcoin SPV ([bitcoin.pdf](https://bitcoin.org/bitcoin.pdf) §8) plus eclipse
([eprint 2015/263](https://eprint.iacr.org/2015/263)) and July 2015 SPV
mining: hashrate that follows headers without checking validity is not
honest majority. Attestor-majority is the same failure with cheaper keys.

### 4.3 Weak subjectivity is the honest name for CPU nodes

Buterin, [Proof of Stake: How I Learned to Love Weak Subjectivity](https://blog.ethereum.org/2014/11/25/proof-stake-learned-love-weak-subjectivity).
A new CPU node cannot distinguish “honest GPU replayed this” from “M keys
lied” from genesis plus protocol rules. Open attestors do not remove that
in Epoch A. Label it.

Bitcoin checkpoints pin a **dead hash**. A trusted pubkey is a **live
oracle**. `assumevalid` ([bitcoin#9484](https://github.com/bitcoin/bitcoin/pull/9484))
skips scripts under a buried hash and does not freeze fork choice — the
right analogy for skipping ExactReplay on *history*, the wrong analogy for
tip admission.

assumeutxo (compiled `(height, hash, txoutset)`) is how historical UTXO
bootstrap already works. Historical ExactReplay for CPU nodes should look
like that: a release pin, not “ask the live GPU.”

### 4.4 Committee selection needs a Sybil weight we do not have

Algorand VRF sortition ([eprint 2017/454](https://eprint.iacr.org/2017/454))
weights by stake. Ethereum committees weight by bonded ETH. VRF over “any
GPU secp key” is Sybil: cheap keys, expensive GPUs, signatures that do not
prove the GPU ran. RANDAO last-revealer bias is fatal if the committee *is*
the ExactReplay oracle.

Honest 0.34 use: VRF may sample who **audits** (load-shed). It must not
sample who **makes the block valid**.

### 4.5 Signatures: keep names, do not FROST the open set

[FROST RFC 9591](https://www.rfc-editor.org/rfc/rfc9591) produces one group
Schnorr. A light client that sees two conflicting group signatures cannot
name the subset. Today’s per-key ECDSA `(pubkey, sig)` is a public
polygraph: two statements, same key, same height, two hashes.

FROST is for a **closed operator committee** that wants compact wire
format. Open set wants naive individual signatures until Epoch C proofs
make the subset uninteresting.

Accountable equivocation ([Casper FFG](https://arxiv.org/abs/1710.09437),
[Polygraph](https://eprint.iacr.org/2019/587)) **names** the fault. Without
a bond it does not **burn**. Still worth gossiping the pair.

### 4.6 Watchtowers, CT logs, Filecoin audits — the usable analog

Lightning watchtowers (Dryja 2016; [eprint 2019/986](https://eprint.iacr.org/2019/986)):
not consensus. 1-of-N honest observers. Justice tx uses evidence the chain
already accepts. They do not call the channel owner to rebuild history.

Certificate Transparency ([RFC 9162](https://www.rfc-editor.org/rfc/rfc9162.html)):
append-only Merkle log, signed tree heads, inclusion/consistency proofs,
gossip of split views. A log can include a bad leaf; it cannot silently
rewrite yesterday. Distrust is social (drop the log), not slashing.

Filecoin WindowPoSt ([spec](https://spec.filecoin.io/algorithms/pos/post/),
[FIP-0010](https://github.com/filecoin-project/FIPs/blob/master/FIPS/fip-0010.md)):
expensive seal, then periodic audit. Optimistic accept + dispute window.
**Admission** is “prove you still have the GPU,” not “your secp key is a
miner.” Putting WindowPoSt into *block validity* would be Epoch B, not
0.34 attestors.

OpenTimestamps: calendars can lie about pending commitments; they cannot
fake a Merkle path into a buried Bitcoin tx. CPU archives = calendars.
The buried object is a compiled pin or a log root consensus GPUs have
ExactReplayed.

Cosmos light client ([arXiv:2010.07031](https://arxiv.org/abs/2010.07031),
[ICS-007](https://github.com/cosmos/ibc/tree/main/spec/client/ics-007-tendermint-client)):
trusting period + ≥1/3 overlap. Stolen **old** keys are useless. Lunatic
headers (invalid but signed) still need a predicate cheaper than “another
signature.” For BTX that predicate is ExactReplay (watchtower) or, later,
a succinct proof.

Mina / Coda ([eprint 2020/352](https://eprint.iacr.org/2020/352)): Epoch C
destination. Constant-size state proof. 0.34 must not pretend sidecar ECDSA
is a SNARK.

EigenLayer AVS: optional collateral for sidecar attestors. Fork choice that
requires an AVS certificate is restaked Liquid.

Celestia DAS: answers “was the body published?” ExactReplay is the scarce
resource, not data availability.

Komargodski et al. ([arXiv:2504.09971](https://arxiv.org/abs/2504.09971)):
why mining is GPU MatMul. Not a light-client ExactReplay certificate.
Non-outsourceable puzzles ([Miller et al. CCS 2015](https://doi.org/10.1145/2810103.2813621)):
ECDSA attestation is **maximally outsourceable** (sign without a GPU). Only
a succinct proof (or a live WindowReplay a GPU must answer) binds “this key
ran ExactReplay.”

## 5. Recommended 0.34 architecture

Ship as three slices. All keep signatures **out of the 182-byte header**
and **out of `CheckBlock`**.

### Slice A — policy and directory (no new crypto)

Goal: stop treating a static operator 1-of-2 pin as *the network’s* PoW,
without breaking CPU archives that still need a pin.

- Document three postures in operator docs: `consensus` (ExactReplay),
  `trusted` (weakly subjective, **your** M-of-N), `economic`/`spv` (not
  mainnet full nodes).
- Default shipped pin may remain as a **DNS-seed analog** (hint), with
  `M≥2` recommended and `M=1` the existing loud warning.
- RPC: `getmatmulattestors` / extend `getmatmultrustedstatus` with
  *heard-but-unpinned* keys (directory, not trust). Never apply a peer’s
  key list as membership.
- Miners: GBT remains legal on any ExactReplay-valid parent. Attested tip
  is a **hint** for CPU catch-up, not a consensus parent rule.
- Do not collocate miner loop and attestation WIF.
- Historical GETMMATTEST: archives only; signers keep today’s windows.

This is Phase 2 of the GPU-transition doc done honestly: more independent
GPUs, `N` grows, `M` is a majority of **the client’s** set, not “anyone
who gossips a bit is M.”

### Slice B — open speak + watchtower refute

Goal: any GPU that ExactReplays may `SignLocal` with its own key and
gossip `MMATTEST`. CPU clients that pin that key count it. CPU clients
that do not pin it still **store and relay** (today `UntrustedSigner`
drops before that is useful as a directory).

Changes:

1. Split `VerifyAttestation` into **cryptographic validity** (chain,
   context, sig) vs **membership** (local pin). Valid-but-unpinned
   statements go to a bounded *heard* store for directory/watchtowers,
   not into quorum.
2. Equivocation object: same key, same height, two hashes → gossip, log,
   freeze that key locally (Cosmos-style). Keep per-key ECDSA.
3. Watchtower refutation: a consensus GPU publishes a signed statement
   that ExactReplay **failed** (or a compact “lunatic” object pointing at
   the hash). CPU trusted nodes: optimistic follow of pinned quorum;
   freeze/drop the hash if a refutation arrives within Δ.
4. Optional Filecoin-style **WindowReplay** as *log data*: a random
   buried height from a log root; attestor must ExactReplay and sign.
   Failure → clients drop the key. Stolen laptop WIF without GPU fails
   the next audit. This is **not** block validity.

Prestwich’s Altair critique is answered without consensus slashing: lying
is −EV if ≥1 honest GPU watchtower exists.

### Slice C — attestation transparency log + compiled pins

Goal: historical GETMMATTEST never hits live GPU; theft cannot rewrite
yesterday.

- Append-only Merkle log of v2 statements (CT / BEEFY-MMR shape).
- Signed tree head (STH) near tip only.
- Archives serve inclusion/consistency proofs. IBD uses proofs against a
  **compiled** `(height, blockhash, log_root)` pin, same moral status as
  assumeutxo / assumevalid.
- `loadtxoutset` stays the UTXO pin; do not make `loadtxoutsetattested`
  a consensus path.
- Cosmos trusting period: keys older than T cannot move a CPU client’s
  tip without a fresh WindowReplay.

This is the OpenTimestamps split: calendars (archives) for freshness,
buried pin for history.

### Explicit non-goals for 0.34

- Attestation bits or aggregates in the block header
- Consensus `nAuthenticatedChainWork` requiring quorum
- On-chain attestor registry that `CheckBlock` reads
- FROST/BLS aggregation of the open set
- FlyClient/NIPoPoW as a substitute for ExactReplay
- EigenLayer/AVS certificates as fork choice
- Putting WindowReplay proofs into block validity (that is Epoch B-shaped)
- Historical ExactReplay regen on signers

## 7. Mapping onto epochs and GPU-transition phases

| When | Authority | Attestor role |
|---|---|---|
| 0.33.4.x (now) | ExactReplay | Closed operator pin; 1-of-2 availability |
| **0.34 Slice A–C** | ExactReplay | Open *speak*; client-local *rule*; log+pins+watchtowers |
| Discovery relays | ExactReplay (archives follow GPU pin) | DNS/addnode hosts are ADDR-only; not authority |
| Epoch B | Proof **and** ExactReplay | Watchtower cost falls (CPU can check durable proof) |
| Epoch C | Succinct proof | Attestors optional; FlyClient-class clients verify proofs |
| Epoch D | Profile 2 + proof | Same light-client story, heavier workload |

## 8. Implementation (local)

Code on this branch (not a version bump). After adversarial review, **open
keys are not HasQuorum**. That would have been a larger Liquid, not
Nakamoto-style GPU consensus: feeding admitted GPUs into the pin skip
would mint fake work with cheap signatures.

What 0.34 actually does:

- `HasQuorum(H)` = pin M-of-N only. Open/admitted keys are a directory.
- Consensus miners (with or without a pin) always ExactReplay. Pin quorum
  never skips GPU and is not FindMostWorkChain or getblocktemplate fork
  choice on consensus. `SkipExactReplayForGpuAttestation` is
  `trusted_mirror && has_valid_gpu_attestation`.
- Trusted mirrors (`-matmulvalidation=trusted`) skip ExactReplay on pin
  quorum, and pin M-of-N still steers FMWC/GBT for those CPU archives
  (weak subjectivity; they cannot GPU-verify).
- `HistoricalExactReplayCoveredByPinQuorum(trusted_mirror, direct_quorum,
  frontier_covers)` is GETMMATTEST serve-budget only, not ConnectTip
  validity. Direct pin quorum may skip CUDA regen; frontier ancestry only
  on trusted mirrors. Skip never writes `BLOCK_EXACT_REPLAY_VERIFIED`.
  `BLOCK_TRUSTED_REPLAY_ATTESTED` persists only on a trusted mirror when
  the pin covers that hash (`MayPersistTrustedReplayAttestationBit`).
- `FindUniqueCompetingAttestedIndex` is trusted-mirror or local-signer
  recovery only (`PinSteersFindUniqueCompetingAttestedIndex`).
- Independent GPU miners already produce consensus-valid blocks by
  ExactReplay without being in the pin. That is the Bitcoin analog.
- Open attestors may *speak* (`Heard`) when `-matmulopenattestors=1`
  (default 0). Co-signing a pin-quorum hash lists them in
  `getmatmulattestors` (operator directory / Phase 2 ceremony), not
  automatic SkipExactReplay. Maps are capped.
- Equivocation freezes an open key in that directory. Pin keys are not frozen.
- Watchtower `mmatrefute` blocks the directory open-quorum *signal* on a
  hash once **pin M** distinct pin members refute; pin quorum is unchanged.
  Ingress shares the MMATTEST token/verify budget and requires a known
  non-failed Profile-1 header.
- Heard MMATTEST does not advance BestKnown, signed frontier, or GETDATA.
- Manual attestation key blocklist (`-matmulattestationblocklist`,
  `addmatmulattestationblocklist`): a blocked key is inert for pin votes,
  open admission, refutations, and `IsAuthoritySigner`, even if it remains
  in the pin. Fail-closed: the node refuses a block that would leave
  fewer than M unblocked pin members. Never auto-populated from peer
  counts or open-attestor majority (that is Sybil).
- Do not bump `CLIENT_VERSION` to 0.34 on this branch.

0.34 does **not** fix 0.33 P2P stalls (`in_flight=0`, GETDATA vs tip,
HEADER_ONLY twins, GETMMATTEST windows, EncDr). Those remain the 0.33.4
line. Opening more signing keys into HasQuorum would have multiplied
signed twins and made those stalls worse.
