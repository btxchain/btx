Status: **PR branch** `pr/0.34-open-attestor-framework`. Not
consensus. Not a release cut. Not a merge to main.

Companion to:

This document answers the external comment that 0.34 **must** address:

> Someone could arrive with massive computing power to easily mine blocks,
> reorganize the chain in their favor, and then disappear; this would freeze
> the blockchain due to long processing times, trigger the difficulty rescue
> mechanism (causing the difficulty to drop), and then allow them to repeat
> the process. Therefore we must also ensure that the issues we experienced
> at the beginning do not recur.

That is not hypothetical. It is the 2026-08-10/11 rented-hashpower loop
(151-block and 8-block rewrites) plus the ASERT dump to historical
`powLimit`, the wall-clock stall that crashed bits, the EncDr 22h gap at
199298, and the easy beginning-of-chain lottery.

## 0. Verdict

**The loop is closed on the 0.34 default config.** No ASERT / F / EncDr
reseal is required or permitted on this branch. 0.34 does not create a new
bypass via Heard, open keys, or the attestation blocklist.

| Step in the comment | Status under default 0.34 |
|---|---|
| (1) Burst ExactReplay hashpower mines a heavier private fork | OPEN (inherent PoW). No cheaper 0.34 route via signatures. |
| (2) Publishes and reorgs (151-block / 8-block shape) | CLOSED. EMERGENCY `PARK` at depth 6 before `DisconnectTip`. |
| (2b) Dumps a live-tip **extension** burst (40–80 future-stamped blocks) | CLOSED locally. Cadence hold (`-cadenceburstmax=3`) paces GETDATA/ConnectTip to 90s. Not consensus. |
| (3) Freeze on ExactReplay / ConnectTip / FMWC of the deep rewrite | CLOSED. Park fires first; unattested competing bodies stay off the GPU; parked branches do not re-spend ExactReplay. |
| (4) “Difficulty rescue” dumps bits | CLOSED. Stall-recovery 199299 is **1/1 inherit, not a dump**. Ease floors at F (`0x1f0a3d70`) from 191714. |
| (5) Attacker disappears | OPEN (inherent). Honest nodes stay on the parked tip. Liveness is operator unpark / honest mining, not an automatic dump. |
| (6) Repeat: bits now easy, lottery again | CLOSED. Next deep rewrite parks again. Bits cannot go easier than F at/after 191714. |
| Beginning-of-chain rewrite / pre-F lottery | CLOSED below checkpoint 186000. Residual band (186000, 191714] is accept-with-doc (WARN-profile / fresh-sync only). |

**Do not** cap `TrustedMirrorMayAdoptCompetingAttestedIndex`’s signed-frontier
exception at park depth: that is the 2026-08-16 archive catch-up path (13–180
blocks behind). Tightening it re-breaks CPU archives. Stolen **T=1 pin** plus
an attested deep fork can still move **trusted mirrors** started with
`-allowsinglekeytrustedmirror=1` and **local-signer miners**. Default 0.34
**refuses** mainnet trusted T=1. The remaining Liquid contract is M=2 plus
the override hatch. See [`0.34-operator-safeguards.md`](0.34-operator-safeguards.md).

## 1. Map the comment onto this tree

### 1.1 Burst hashpower (step 1)

Nothing in Bitcoin-shaped PoW stops private mining. 0.34 does **not** make
this cheaper:

- Open keys are `Heard` only (`ShouldAdvanceBestKnownFromMmAttest` is
  `Accepted`/`Duplicate`).
- `HasQuorumLocked` is pin votes only.
- `SkipExactReplayForGpuAttestation` skips iff **trusted mirror and pin
  quorum**. Consensus miners ExactReplay.
- `PinSteersFindUniqueCompetingAttestedIndex` is false for consensus+pin
  with no local WIF, so a foreign pin cannot buy fork choice on a full node.

### 1.2 Publish and reorg (step 2)

`ActivateBestChainStep` (`src/validation.cpp`): default profile
`ReorgProtectionProfile::EMERGENCY` → `DeepReorgAction::PARK`,
`park_depth = 6`, armed at `nReorgProtectionStartHeight` (61000). Predicate
`kernel::DeepReorgShouldPark`. The 151-block and 8-block shapes both park
**before** the disconnect/connect loop (`ParkReorgBranch` +
`EraseParkedBlockIndexCandidates`).

Park escapes, and why an unkeyed attacker cannot use them:

| Escape | Arms when | Unkeyed 151-block dump |
|---|---|---|
| `IsAutomaticReorgRecoveryCandidate` | `MaybeTrackReorgRecovery` only if `WorkBasedReorgRecoveryMayArm` (`1 <= depth <= park_depth`) | A 151-block rewrite **does not arm**. That is dump-and-run defense, not a gap: extending the window would let a rewrite that ExactReplays itself auto-unpark. Consensus miners unpark parked branches with `reconsiderblock`. |
| `IsAttestedAbandonForkCandidate` | `candidate == FindUniqueCompetingAttestedIndex()` | Unattested fork: `consider()` drops it. Consensus-no-signer: FindUnique returns `nullptr`. Trusted mirrors / local signers may still auto-release a unique attested parked branch. |

`recovery_escape` is therefore false. `DeepReorgShouldPark` is true.

Operator override `-parkdeepreorg=0` / `-reorgprotectionprofile=archive`
(WARN, park disabled) reopens step 2. That is an operator choice, not the
default. **Do not disable emergency parking** on public archives that are
supposed to resist dump-and-run.

### 1.2b Live-tip extension burst (cadence hold)

PARK does **not** fire on an **extension** of the current tip
(`pindexFork == pindexOldTip` ⇒ `reorg_depth == 0`). A renter can
pre-generate 40–80 valid headers with `nTime += 90` (the 2h
`MAX_FUTURE_BLOCK_TIME` wall cap is the only binding limit at +90/step;
MTP+3600 and parent+1080 are not), dump them in seconds, and force this
node through 40–80 ExactReplay `ConnectTip`s plus an instant height jump.

That is local **cadence hold**, not consensus invalidity:

- Predicate `kernel::CadenceHoldShouldHold` / `CadenceHoldAllowedHeight`
  (`src/kernel/chainstatemanager_opts.h`). Origin walk
  `CadenceHoldOrigin` is not the production extra source (attackers stamp
  `nTime <= now` and would re-roll it). Production pins a **wall-clock
  anchor** (`ArmCadenceHoldAnchor`) at the live tip when the hold first
  fires; the horizon then advances one height per 90s of `GetTime()`.
- Default `-cadenceburstmax=3` on **mainnet emergency** (ApplyArgsManOptions;
  BasicTestingSetup is MAIN so it sees this). `0` on other profiles and
  non-mainnet. Options constructed without ApplyArgsManOptions stay at 0
  so isolated unit mining is not throttled. Disable with
  `-cadenceburstmax=0`.
- `ActivateBestChainStep` holds competing shallow dumps (`fork_depth <=
  park_depth`) without `DisconnectTip`. Extensions connect only up to
  the allowed height. Candidates stay in `setBlockIndexCandidates`.
- `FindNextBlocksToDownload` / `HeadersDirectFetchBlocks` clamp GETDATA
  for bodies **this node requests**. Unsolicited `block` messages bypass
  GETDATA; `ConnectTip` + ABC are the backstop. No misbehavior score.
  `BLOCK_TIME_FUTURE` remains a `break`, not a ban.
- A 1s scheduler kick retriggers ABC as wall clock raises the horizon.
- Disarmed on IBD, tip older than `2 * nPowTargetSpacing`, below
  `nReorgProtectionStartHeight` (61000), and `recovery_escape`.

Hijack-brief cadence rows (no reseal, no header-PoW, no open `HasQuorum`):

| ID | Verdict | Why |
|---|---|---|
| 2.2 Header pre-aging | **CLOSED** | Production extra is this node's wall-clock tip / `ArmCadenceHoldAnchor`. `CadenceUsableFirstSeenSpan` ignores header arrival. `CadenceHoldUsesHeaderArrivalAsExtra` is false. `CadenceFirstSeenLooksLikeDump` is **not** OR'd into the hold (that would be a permanent freeze). |
| 2.3 Slow-drip / honest 90s trickle | **ACCEPT-WITH-DOC** (inherent PoW) | Extra after `burst_max` is +1 per `nPowTargetSpacing`. A withheld majority that trickles at honest cadence **is** Nakamoto. Holding it forever would be a finality gadget. |
| 2.4 Empty restart first-seen | **CLOSED** (dump path); persist-across-restart **ACCEPT-WITH-DOC** | `CadenceHoldRestartLeavesHoldArmed` keeps extra=0. Idle credit is `CadenceHoldAllowedHeight` (never INT_MAX). Persisting first-seen is not 0.34 state: extra=0 is fail-closed, not a dump window. Restart-only recovery of a *stall* is still an unprivileged-node failure, not this vector. |

This is **policy pacing of visible cadence**, not finality. Residual: the
2h future window still admits ~80 legal headers; the hold is the
mitigation. A stale-tip / partition catch-up is intentionally full speed.

**Not** done (rejected): invalidating future-stamped headers; tightening
`MAX_FUTURE_BLOCK_TIME` as the primary fix; synthetic park on live-tip
+N (split-risk memo); enabling header-PoW; ASERT/F/EncDr reseal;
auto-51% from peer/attestor counts; erasing held candidates.

Compressed MTP+1 timestamps while mining wall-clock-fast are **not** a
burst tool: ASERT eases ~0.43%/block and the F floor binds. Do not
reseal τ/F.

### 1.3 Freeze on long processing (step 3)

Park is not enough if the node still ExactReplays 151 junk bodies.

- `ActivateBestChainStep` parks before `ConnectTip` of the deep rewrite.
- `FindMostWorkChain` skip budget `kFindMostWorkSkipBudget{128}`; HEADER_ONLY
  holes are erased before the park check; FindUnique is gated.
- Independent consensus ExactReplay (`IndependentConsensusMaySpendExactReplayGpu`):
  unattested competing twins stay **off** the device. Covered hashes still
  replay so ConnectTip can take a *short* attested race. Parked branches
  return false (`on_parked`).
- `MatMulMaySpendExactReplayGpu` fail-closes on `IsOnParkedReorgBranch`.
- Header-first ExactReplay is near-tip only (`MATMUL_RC_NEAR_TIP_DEPTH = 3`).
- Trusted mirrors never P2P-ExactReplay.

Residual DoS (no reorg): cheap HEADER_ONLY towers (audit C1; header-PoW gate
stays **disabled**). Bounded by headersync commitments and the FMWC budget.
Do not enable header-PoW as an ExactReplay substitute.

Shared ExactReplay pending slots: competing (non-AuthenticatedTipChild)
jobs use `CanStartCompetingMatMulRCVerification`, which leaves
`MATMUL_RESERVED_AUTHENTICATED_TIP_CHILD_SLOTS` of the RC pending cap free.
On the production default (one RC job) competing ExactReplay cannot start.
That closes freeze-DoS M1 monopoly of the honest tip-child lane. It does
not connect a 151-block rewrite, and it does not dump bits. HEADER_ONLY
towers can still invert the *followed* progress-budget bypass (audit C1);
document, do not enable header-PoW.

### 1.4 “Difficulty rescue” (step 4)

There is **no live dump**. The EncDr stall-recovery flag day at **199299**
is `nMatMulStallRecoveryAsertNum/Den = 1/1`: inherit parent bits, re-anchor,
forget the 22h gap. It does **not** multiply the target.

Live easing is ordinary ASERT (`CalculateMatMulAsertTarget`) with:

- F floor `powLimitUpgrade` compact `0x1f0a3d70` at height **191714**
  (`MatMulAsertPowLimitForNextHeight`). Historical `powLimit` `0x2066c154`
  is ~2000× easier and is **unreachable** at/after 191714.
- τ **14400** at **191715** (4× slower than the old 3600).
- MTP+3600 `MaxMatMulFutureBlockTime` from **118482**. This is the
  binding easing ceiling (~7× target mean advance via the eleven-block
  median). `nMatMulMaxBlockTimeAdvance` (+1080 from 199299) is a
  per-block transient, not the lever. 0.34 does not retune either.
- `ContextualCheckBlockHeader` exact `nBits` (`bad-diffbits`).

A freeze (park, blocklist fail-closed, no blocks) **does not retarget**.
`GetNextWorkRequired` runs only on an accepted header. When mining resumes,
the first nTime is capped (~1080 s parent / MTP+3600) so a 22h gap is about
1.05× ease, then a slow drain toward F, never below F.

ASERT `time_diff` is measured from the re-anchor **block itself**, while
`CalculateMatMulAsertTarget` still charges `height_diff + 1`. That pairing
is shipped mainnet behavior (~0.43% harder at the first post-reanchor
block; matched at 199299→199300). 0.34 does **not** reseal it and must
**not** add another ASERT re-anchor.

### 1.5 Attacker leaves and repeats (steps 5–6)

Departure is inherent. The next deep rewrite parks again. Bits cannot dump
below F. The 2026-08-10/11 outcome (ease to lottery, 151-block rewrite,
repeat) cannot recur under default config.

**Honest remaining Nakamoto surface:** burst ExactReplay hashpower can still
win **shallow** (1–5 block) races at the F floor. That is PoW, not the
dump-and-run loop.

**Honest remaining economic surface:** a dominant producer can *harden* bits
to their rate, leave, and leave honest miners grinding at the pumped
difficulty. There is no automatic dump to rescue them. Resumption is grind
or an operator 1/1 flag-day (the 199299 pattern). After resumption the
attacker can walk bits down to F over hundreds of cap-sat blocks. F is the
frozen consensus floor; 0.34 must not reseal it.

## 2. Beginning-of-chain (must not recur)

| Era | Defense |
|---|---|
| Genesis → last checkpoint **186000** | `bad-fork-prior-to-checkpoint`. `nMinimumChainWork` / `defaultAssumeValid` pin 186000. Fast-mine bootstrap (0–49999 at historical `powLimit`) is checkpoint-locked. |
| EncDr / Epoch A **185000** | Checkpointed; DRLT/RC-coupled disabled on mainnet. |
| DGW easing | Dead on MatMul: `GetNextWorkRequired` routes `fMatMulPOW` to ASERT. All `nDgw*` heights INT32_MAX. |
| (186000, **191714**) | Historical `powLimit` still the ASERT clamp. A fork *above* 186000 can in principle ease to the old lottery. Default EMERGENCY park still refuses a 13k-block rewrite of a running node. WARN-profile, `-parkdeepreorg=0`, `-nocheckpoints`, and **fresh IBD on hostile peers** remain exposed. Hard closure is a later checkpoint above 191714 — operator/chainparams decision, not a 0.34 reseal. |
| ≥ 191714 | F floor. Stall-recovery 199299 is 1/1. assumeutxo snapshots include 199299. |

`nReorgProtectionStartHeight = 61000` disarms park below 61000. Any fork that
passes checkpoint 186000 is above that, so the disarm is harmless for this
attack shape.

## 3. 0.34 must not introduce

| Would-be “fix” | Why it is an attack |
|---|---|
| Heard / open keys as `HasQuorum` | Cheap ECDSA mints fake work; dump-and-run via signatures. |
| Pin skip ExactReplay on consensus | Stolen T=1 pin becomes CheckBlock. |
| Pin steers FindUnique on consensus-no-signer | Stolen pin buys a 151-block park bypass. |
| Cap signed-frontier FindUnique at park depth | Re-breaks 2026-08-16 archive catch-up (13–180 behind). |
| Enable header-PoW as ExactReplay substitute | C1: throttle ≠ authenticated chainwork. |
| Auto-51% from attestor/peer counts | Sybil. |
| New automatic stall dump / F reseal | Repeats 2026-08-10/11. |
| Restart the live GPU attestor / SIGKILL production `btxd` | Zero-downtime rule. |

## 4. Operator steps (not code)

1. Keep the default **emergency** profile. Do not set
   `-reorgprotectionprofile=archive` (WARN, park disabled) on nodes that
   must resist dump-and-run. Archives that need catch-up already have the
   signed-frontier `recovery_escape` on **trusted mirrors**.
2. Raise the pin to **M=2** before any public-miner announcement. T=1 is
   the remaining park bypass on mirrors and local-signer miners.
3. Manual attestation blocklist (`-matmulattestationblocklist`) is
   fail-closed excision, not auto-ban from peer counts.
4. A post-attacker freeze at pumped bits is broken by grinding or an
   operator 1/1 flag-day, never by an automatic dump.
