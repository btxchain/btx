# 0.34 response to pre-launch notes (2026-08-26)

Status: **PR branch** `pr/0.34-open-attestor-framework`.
Not a release cut (`CLIENT_VERSION` stays 0.33.4.x). Not a merge to main.

An outside review of tag `v0.33.4.2` listed seven surviving items on the
surfaces 0.34 is about to land on. The notes file itself is **not** in
this tree (live infrastructure detail). This page is the public-safe
response: what 0.34 changed, what it will not change, and what is an
operator checklist rather than a binary.

Companion: [`0.34-operator-safeguards.md`](0.34-operator-safeguards.md),
[`0.34-dump-and-run-reorg.md`](0.34-dump-and-run-reorg.md),
[`0.34-discovery-relay.md`](0.34-discovery-relay.md).

## §1 Already handled on v0.33.4.2 — no 0.34 code

BIP94 timewarp, clamped-ASERT credit (`MatMulAsertClampedTimeCredit`),
PARK default EMERGENCY depth 6, random tie-break default on,
trust-adjusted work clamp, Phase-1 before ExactReplay, ADDR rate limit /
feelers / test-before-evict / anchors, assumeutxo 199299. Acknowledged.
Do not reseal EncDr / ASERT / F to “improve” any of these.

## §2 Bootstrap / seed diversity — operator, not invented IPs

Fresh-node addrman is only as diverse as DNS seeds plus
`chainparamsseeds.h`. Discovery relays do **not** add day-one addresses.

This PR documents the checklist (`contrib/seeds/README.md`,
`0.34-discovery-relay.md` §6, `chainparams.cpp` comments):

- 6–8 seed operators, not all one ASN, not all the same people who sign
  releases.
- Many A/AAAA per seeder, not one.
- Regenerate `chainparamsseeds.h` from a crawl (Bitcoin PR #18506
  process) so the fixed list is a real fallback.
- Do **not** put `NODE_MATMUL_DISCOVERY` into `SeedsServiceFlags()`. DNS
  x-subdomain must still find `NODE_NETWORK` archives; relays are the
  empty-x ADDR_FETCH fallback.

This binary does not invent seed operators or unpublished addresses.

## §3 `asmap` — opt-in, no map in tree

Implementation is complete; `-asmap` stays opt-in (same as Bitcoin Core).
No `ip_asn.map` ships. A stale map can make eclipse easier. Enable once
the reachable set spans more than one ASN (after §2). Help text says so.

## §4 Checkpoint 186000 has drifted — cadence, no unverified hash

Newest header checkpoint remains height **186000**. `nMinimumChainWork`
and `defaultAssumeValid` stay keyed to that hash. assumeutxo **199299**
is the UTXO snapshot pin, not a header checkpoint; do not copy that hash
into `checkpointData` while it sits in the live tip band (park_depth 6 /
finality 72).

Next release: a verified hash ~100–300 behind a settled tip. Comments in
`chainparams.cpp` record the drift.

## §5 PARK escape for depth > 6 — intentional, not extended

`WorkBasedReorgRecoveryMayArm` is `1 <= depth <= park_depth`. PARK fires
on `depth > park_depth`. Those predicates are mutually exclusive **on
purpose**.

Extending work-based recovery to parked depth would let a dump-and-run
rewrite that ExactReplays itself auto-unpark via
`nAuthenticatedChainWork`. That is the 2026-08-10/11 attack succeeding.

0.34 answer:

- Consensus miners: parked branches stay parked until `reconsiderblock`.
- Trusted mirrors / local signers: still `IsAttestedAbandonForkCandidate`
  (unique attested abandon). Pins skip expensive work and may auto-release
  a parked *attested* branch. They never decide which chain wins
  (`HasQuorum` is not fork choice on a consensus miner).
- Open attestor keys are not `HasQuorum` and do not unpark.

## §6 MTP drift cap is the easing ceiling — comment only

The binding sustained cap is `nMatMulMaxFutureMtpDrift` (MTP+3600 since
118482), not `nMatMulMaxBlockTimeAdvance` (+1080). Mean advance over six
blocks is at most ~600s (~6.7× the 90s target). 0.34 does not retune
either constant. If either is revisited later, MTP+3600 is the dial;
+1080 is a per-block transient.

## §7 ASERT `height_diff+1` vs time from the anchor itself — comment only

`time_diff` is from the re-anchor **block itself**.
`CalculateMatMulAsertTarget` still charges `target_spacing * (height_diff + 1)`.
That pairing is **not** spec aserti3-2d (spec measures from the anchor
parent). It is shipped mainnet behavior: ~0.43% harder at the first
post-reanchor block (matched at 199299→199300).

Do not change the formula. 0.34 must **not** add another ASERT re-anchor.
Comments at both sites record the artifact so the next measurement across
a re-anchor is not mistaken for a hashrate shortfall.

## §8 ExactReplay twin-storm throttle — **code fix in this PR**

v0.33.4.2 gated `MatMulMaySpendExactReplayGpu` on
`matmul_trusted::IsConfigured()`. A consensus miner with no
`-matmultrustedpubkey` ExactReplay'd every qualifying sibling (live
2026-08-14 GPU starve). 0.34's message is that pins are optional
telemetry, which would have turned that throttle off network-wide.

This PR:

- `ExactReplayAdmissionThrottleApplies(exact, pin)` is a function of
  ExactReplay-required, **not** of pin configuration.
- `AdmitMatMulBlockVerification` runs `MatMulMaySpendExactReplayGpu` for
  all consensus roles. Pin skip / retain / GETMMATTEST stay behind
  `IsTrustedMirror`.
- Speculative EncDr RC pending cap is 1 whether or not a pin is
  configured (`MatMulSpeculativeRcPendingLimit`). Open keys must not
  populate `HasQuorum` to keep this armed.

## §9 External finality — not as authority

Attestations skip expensive work on **trusted mirrors** and may
auto-release a unique attested parked branch on those nodes. They never
decide which chain a consensus miner connects or mines. That is the gold
standard. Do not ChainLocks / dPoW / open-`HasQuorum`. §5 work-based
unpark of parked depth is **rejected** (dump-and-run).

Clamped-ASERT and the first drafts of §5/§6 were already corrected in the
notes. No extra work.
