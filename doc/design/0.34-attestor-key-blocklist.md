# 0.34 attestation key blocklist — spec that must land now

Status: **implemented on this local branch**. Not consensus, not a release
cut, not a push. Axioms of
[`0.34-ai-native-bitcoin.md`](0.34-ai-native-bitcoin.md) hold unchanged:
open keys are not `HasQuorum`; consensus miners ExactReplay; Heard does not
move BestKnown; no SNARKs as 0.34 consensus; pin skip stays
trusted-mirror-only.

Related: [`../btx-matmul-trusted-rpc-mirrors.md`](../btx-matmul-trusted-rpc-mirrors.md),
[`0.34-open-attestor-framework.md`](0.34-open-attestor-framework.md),
[`../btx-gpu-verified-network-transition.md`](../btx-gpu-verified-network-transition.md).

## 1. One-line rule

**A blocked attestation key is inert everywhere authority is counted —
pin votes, pin refutations, open admission, open quorum, the durable-miss
path, `IsAuthoritySigner`, and the local signer — and blocking must never
shrink the *unblocked* pin below M.**

The blocklist is the **manual emergency-hijack control** for
[`btx-gpu-verified-network-transition.md`](../btx-gpu-verified-network-transition.md)
Phase 1–2: when a pin member or an open key is compromised or taken over by a
mining pool, an operator cuts it out of *attestation authority* with one
command on every affected node — no code release, no pin re-roll, no restart.
It is not a consensus rule and it is never populated automatically.

## 2. Decision: auto-ban is Sybil; no auto-ban from observed quantities

Operator item 5 asks whether an auto-51% defense from observed network
strength should land. **Decision: no. Do not land any automatic ban keyed on
peer counts, statement counts, admission rate, GETMMATTEST volume, or any
other observed network quantity.** Reasons, in priority order:

1. **Attestation keys are free and carry no work.** ECDSA sidecar statements
   are maximally outsourceable (Miller CCS 2015). Every per-key behavioral
   aggregate — "this key signed 51% of tips", "this key's statements dominate
   GETMMATTEST" — is defeated by key splitting. A Sybil attacker chooses how
   many identities "the largest attestor" has, so an auto-ban on
   largest/dominant observed identity is a **ban the attacker triggers on
   whoever they choose to flood**; it is a griefing vector against legitimate
   attestors, not a defense.
2. **Network *strength* does not bind attestation identity.** ExactReplay
   chainwork is header-bound and key-free; it measures miners, not attestors.
   There is no non-Sybilable observed quantity that attributes "51% of
   network strength" to an attestation key. Any rule would be measuring
   something else (peer counts, heard volumes) that is Sybilled.
3. **Bitcoin-shaped emergency controls are manual.** The Nakamoto analog for
   "a signer federation is hijacked" is human, out-of-band action, not a
   protocol heuristic that an adversary can probe and game. The blocklist
   below is that manual control; its fail-closed pin guard (§5) is what keeps
   it from being *used* as an attack (blocking M-1 keys via RPC still leaves
   M unblocked members, so a hijacker cannot make a mirror accept fewer than
   M real keys).

Consequence: **no auto-ban from peer counts** (operator instruction) and no
auto-ban from any other observed quantity. `getmatmultrustedstatus` may
*report* unblocked-pin count and blocklist membership; nothing in the node
writes to the blocklist except `-matmulattestationblocklist` at startup and
`addmatmulattestationblocklist` from an operator.

## 3. Semantics of a blocked key

A key in the blocklist (`BlockedSigners()`, union of the init arg set and
runtime adds, plus any persisted set restored at startup):

| Surface | Behavior | Where |
|---|---|---|
| `Add()` of a blocked signer | rejected `AddResult::BlocklistedSigner`; never stored, never Heard, never counted, never admitted | `AttestationStore::Add` early return after crypto verify |
| Pin votes | blocked key contributes 0 votes; `PinVotesLocked` counts only `trusted_signers \ blocked` | `PinVotesLocked`, `WouldReachQuorumLocked`, `HasQuorumFromAttestations` |
| `HasQuorumLocked` / `HasQuorum` | `PinQuorumLocked` only, and that now excludes blocked | unchanged callers, new counting |
| Open admission | `AdmitOpenLocked`, `AdmitHeardOnHashLocked`, `AdmitOpenSigner`, `RestoreOpenAttestors`, durable-import admission all skip blocked keys | admission paths |
| Open quorum / directory | blocked keys never count in `AuthorityVotesLocked` or `HasOpenQuorum`; blocked key removed from `m_admitted_open` at block time (directory stays honest) | counting + block action |
| Heard | blocked signer's statement is rejected at `Add`, so nothing enters `m_heard`; previously heard entries by that key are dropped at block time | `Add`, block action |
| Pin refutation (`mmatrefute`) | blocked key does not count toward the pin-M refute veto in `RefreshPinRefutedLocked` | refute counting |
| `IsAuthoritySigner` | false for blocked keys → `RecordHasPinAuthority` cannot mint `BLOCK_TRUSTED_REPLAY_ATTESTED` from a blocked key | node wrapper |
| Local signer | `SignLocal` returns `BlocklistedSigner`; constructor and init refuse a blocked local-signer key (operator misconfig) | `SignLocal`, constructor, init |
| Durable import | records signed by a blocked key are skipped (counted, logged) but never fatal — same posture as `UntrustedSigner` in closed mode | `ImportAttestations`, `OpenPersistence` load |
| `SkipExactReplayForGpuAttestation` | unchanged shape: still `trusted_mirror && HasQuorum(hash)`; HasQuorum now excludes blocked, so a blocked key can no longer trigger the CPU-archive skip | validation, no code change |
| `FindUniqueCompetingAttestedIndex` / FMWC steering | blocked pin key's statements are inert there too because `HasQuorum`/frontier-hint feeds exclude them | no direct change, via counting |

Stored statements signed by a blocked pin key are **kept for audit** (they
remain visible in `getmatmulattestations`/`ExportAll`) but are inert in every
counting path; they are never deleted by blocking, so an operator can see who
was cut out and why.

## 4. StoreConfig / Store API

`src/matmul/trusted_exact_replay_attestation.h` / `.cpp`:

- `StoreConfig.blocklist` — `std::vector<CPubKey>`; empty by default. Every
  entry must be a canonical compressed key (`IsCanonicalSigner`); duplicates
  are a config error (same style as `trusted_signers`).
- Store state: `std::set<CPubKey> m_blocked;`.
- Constructor additions, in order after the existing signer/threshold checks:
  1. validate blocklist entries (canonical, distinct, disjoint from nothing —
     overlap with `trusted_signers` is legal and is the point);
  2. **fail-closed:** require
     `UnblockedPinMembersLocked() = |m_trusted_signers \ m_blocked| >= m_config.threshold`,
     else throw `std::invalid_argument` ("blocklist leaves fewer than M
     unblocked trusted signers");
  3. require `m_config.local_signer` pubkey not blocked, else throw.
- New public API:
  - `[[nodiscard]] bool IsBlocked(const CPubKey&) const;`
  - `[[nodiscard]] std::set<CPubKey> BlockedSigners() const;`
  - `[[nodiscard]] size_t UnblockedPinMembers() const;`
  - `enum class BlocklistResult : uint8_t { Blocked, Duplicate, WouldDisablePinQuorum, LocalSigner, Unknown }` (or reuse a small enum) and
    `[[nodiscard]] BlocklistResult AddBlocklistedSigner(const CPubKey&);`
    — adds a key to `m_blocked`, drops it from `m_admitted_open`, drops its
    `m_heard` entries (blocked open keys are removed like a freeze, but the
    key is *not* added to `m_frozen_open`: freeze is equivocation, blocklist
    is operator policy; `getmatmulattestors` reports the two separately),
    and returns `WouldDisablePinQuorum` **without applying** when
    `UnblockedPinMembersLocked() < m_config.threshold` after the add. Adding
    an already-blocked key returns `Duplicate`; adding the local signer key
    returns `LocalSigner`. Blocking a never-seen key is allowed (prophylactic).
  - No runtime **remove** in this landing: unblocking is a deliberate restart
    with the arg removed / persisted entry edited, so a compromised RPC
    session cannot silently clear the emergency control. (Fail-closed and
    continuity both point this way: a blocked hijacker key must not be
    re-enabled by a second compromise.)
- `AddResult::BlocklistedSigner` (new value; `AddResultName` returns
  `"blocklisted-signer"`). No change to `VerifyResult`/`VerifyAttestation`
  membership variant: the store is the policy gate; `Add()` and all counting
  paths enforce it. `ImportAttestations` treats `BlocklistedSigner` as a
  benign skip.
- Counting-path edits (all consult `IsBlocked`):
  `PinVotesLocked`, `AuthorityVotesLocked`, `WouldReachQuorumLocked`,
  `HasQuorumFromAttestations`, `HasOpenQuorum` (its direct vote loop),
  `RefreshPinRefutedLocked`, `AdmitOpenLocked`, `AdmitOpenSigner`,
  `RestoreOpenAttestors`, `SignLocal` (pre-check local key), `IsAuthoritySigner`.

## 5. Fail-closed definition

`UnblockedPinMembers() < M` must be **unreachable in every running state**:

1. **Startup (init + constructor):** `InitError` (and constructor throw) when
   `|pin \ blocklist| < M` — including the persisted-set merge. A trusted
   mirror never starts with an M it cannot actually reach; a consensus+pin
   node never starts pretending a blocked key is telemetry.
2. **Runtime add:** `addmatmulattestationblocklist` returns
   `RPC_INVALID_PARAMETER` and applies nothing when the add would leave
   `UnblockedPinMembers() < M`.
3. **Counting:** quorum is `>= M` *unblocked* pin votes, so even if some
   future code path evades 1–2, no block can reach quorum with fewer than M
   unblocked members — the mirror stalls rather than accepting reduced
   authority. Stalling is the correct failure mode for a CPU archive.
4. **Redundancy warning:** mainnet warning when
   `UnblockedPinMembers() == M` (no spare unblocked member left); the existing
   1-of-1 / M<2 warnings should compute against the *unblocked* set so the
   message matches reality after a blocklist is applied.

The blocklist never lowers M, never changes `nBits`/ASERT, never touches
`CheckBlock` or the 182-byte header, and never changes what a consensus node
(no pin, or with pin) must ExactReplay. It only prunes who may *attest*.

## 6. init flag

`src/init.cpp`, same block as `-matmultrustedpubkey`:

- `argsman.AddArg("-matmulattestationblocklist=<hex>", "Compressed secp256k1
  public key whose attestations are never counted, even if it is in
  -matmultrustedpubkey. Repeat for multiple keys. Emergency manual hijack
  control only; never auto-populated. Starting or adding a block that leaves
  fewer than -matmultrustedthreshold unblocked pin members is refused
  (fail-closed). Restart without the flag (or edit the persisted list) to
  unblock.", ALLOW_ANY, OPTIONS)`.
- Parse like `-matmultrustedpubkey`: `ParseHex`, require compressed + fully
  valid, reject duplicates within the flag (and within the flag ∪ persisted
  set), canonical error text.
- Append to `StoreConfig.blocklist` before `StageConfiguration`; the
  constructor enforces §5.1. The mainnet warning code paths compute
  `preliminary_signer_capacity` as unblocked count.
- Consensus nodes with no pin but a blocklist: allowed (prophylactic, and the
  list still gates open admission/serve telemetry); the flag requires
  `attestation_config_requested` to be true like the other matmul args.

## 7. RPC (runtime)

`src/rpc/matmul_trusted.cpp`, registered under `"mining"` like the rest:

- `addmatmulattestationblocklist <pubkey>` — one canonical compressed pubkey
  hex. Returns `{added: bool, result: "blocked"|"duplicate"|"would-disable-pin-quorum"|"local-signer", blocked_pubkeys: [...], unblocked_pin_members: n, threshold: m}`. `would-disable-pin-quorum` and `local-signer` are `RPC_INVALID_PARAMETER` with the object included and **no state change**. Requires `IsConfigured()`, same guard as `submitmatmulrefutation`. Persists the add (§8).
- `listmatmulattestationblocklist` — returns
  `{blocked_pubkeys: [...], persisted: bool, unblocked_pin_members: n, threshold: m, fail_closed: true}`. `fail_closed` is always `true` in this design (the guard is structural); it is reported so monitoring can assert it.
- Extend `getmatmultrustedstatus` and `getmatmulattestors` with
  `blocked_pubkeys`, `unblocked_pin_members`, and `threshold` already present
  (recomputed against unblocked set), so alerting on "archive about to lose
  quorum" works without a new polling loop. `getmatmulattestors`
  `pinned_pubkeys` still lists the full configured pin (audit) and
  `blocked_pubkeys` marks which are inert.

## 8. Persistence and continuity (archive requirement)

- Runtime adds survive restart: a `DurableBlocklistKey{prefix 'b', uint256
  chain_id}` record in the existing durable LevelDB (`OpenPersistence`),
  written on each successful `addmatmulattestationblocklist` (immediate small
  write, same DB, no new file).
- Keyed by **chain_id only, not `AuthorityNamespace`**: a pin rotation must
  not silently un-block a hijacked key. Trade-off (a block survives a network
  change) is accepted; the list is tiny and operator-editable.
- At startup: `-matmulattestationblocklist` ∪ persisted set is the effective
  blocklist; if the union violates §5.1 → `InitError` (fail-closed, and the
  error names the keys and the unblocked count). `listmatmulattestationblocklist`
  reports `persisted` so an operator who un-blocks via restart knows whether
  the persisted record still needs editing.
- This is what makes requirement 3 ("stop running operator attestors
  forever") safe: the unattended archive follows its pin; an emergency block
  is not silently lost on the next upgrade/restart.

## 10. Operator requirement mapping

- **(1) 0.33.x CPU-archive work survives 0.34:** additive config, empty by
  default, no protocol/consensus/header change; trusted-mirror pin skip
  unchanged in shape; a fleet that never sets the flag is byte-identical in
  behavior.
- **(2) Decentralized ExactReplay without disruption:** the blocklist prunes
  *attestation authority* only; consensus miners still ExactReplay; no fork,
  no GBT/FMWC change on consensus; no key enters or leaves `HasQuorum`
  automatically.
- **(3) Archives follow network strength unless emergency hijack:** normal
  path untouched (pin-follow, Phase 3 when CPU archives gain GPUs); the
  blocklist is precisely the "emergency hijack" instrument, and persistence
  (§8) keeps it effective across restarts. Auto-follow/auto-51% does **not**
  land (§2).
- **(4) Mining pools cannot take over attestation:** open keys stay out of
  `HasQuorum` (axiom); pin admission stays local config; a pool that gains
  control of a pin key or floods open keys is cut out with one RPC call on
  each node, and the fail-closed guard means the blocklist itself cannot be
  used to drop an archive below M.
- **(5) Auto-51% defense:** decision is **no — Sybil** (§2). Manual only.
