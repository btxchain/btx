This document answers one question: **in what order do we roll out 0.34 so
that 0.33.x CPU-archive light-client work survives, ExactReplay
decentralizes without disruption or hijack, and operator attestors become
optional — while the hard axioms hold?**

## 0. Operator asks → answers

## 1. The auto-51% decision: observed network strength is Sybil

**Decision: reject "auto-51% defense from observed network strength" as a
protocol mechanism.** It is Sybil for the same reason open attestations
cannot be `HasQuorum`:

- An open key is an unbonded secp256k1 ECDSA key that does **not** prove a
  GPU ran ExactReplay (Miller CCS 2015: maximally outsourceable). A pool
  mints `10^4` keys for pennies and floods `Heard`, peers, and directory
  counts. "Most attestors bless this chain" then means "most cheap keys
  bless this chain" — a key-count lottery, i.e. Liquid with more seats.
- There is no Sybil weight in Epoch A. Algorand/VRF sortition weights by
  stake we do not have; Ethereum committees weight by bonded ETH we do not
  have; RANDAO last-revealer bias is fatal if the sampled committee is the
  ExactReplay oracle (see 0.34-open-attestor-framework.md §4.4).
- Observed strength is self-referential: whoever controls the attestation
  channel controls the observation. An eclipse/51% attacker is exactly the
  case where "observed network strength" lies.
- The non-Sybil strength signal already exists: **ExactReplay-verified
  chainwork** (authenticated chainwork on consensus nodes) plus ASERT
  difficulty. Freivalds-verified pool shares make pooling trustless and
  proportional. A 51% coalition of real hashrate is defended the same way
  Bitcoin defends it — economically — plus v4's hardware base; no protocol
  gadget changes that (btx-matmul-v4.2-longevity-threat-model.md §2d).

**What CPU archives actually get.** "Archives follow network strength" is
satisfied honestly as weak subjectivity: the archive follows the chain its
pin attests; the operator keeps the pin aligned with the ExactReplay-verified
chain; a **manual emergency override** exists for the documented hijack
window (§6). Automatic anything derived from observed gossip is rejected.

**What stays allowed.** Observed network strength (attestor counts, peer
tip counts, chaintip census) is **telemetry**: `getmatmultrustedstatus`,
watchtower refutations, anomaly monitors, alerting. Telemetry may trigger a
**human** review; it never moves BestKnown, never changes admission, never
skips ExactReplay, never freezes or unfreezes keys.

## 2. Strong attestation blocklist (pools cannot take over attestation)

New, client-local, release-compiled mechanism. The **primary** defense is
already structural — open keys have no authority — and the blocklist is the
operator-side excision layer on top.

**Mechanism.** `-matmulattestationblocklist=<pubkey>` (repeatable). A
blocklisted key:

- is never counted toward pin `M`, even if also present in
  `-matmultrustedpubkey` — a conflicting config is a **startup error with a
  loud warning**, not silent precedence;
- is not stored, not even as `Heard`; its statements are not relayed and
  not served;
- is shown as suppressed in `getmatmulattestors`;
- its equivocation records are dropped unless they are refutation evidence.

**Anti-censorship and anti-poison guards (non-negotiable).**

- The blocklist is **client-local and release-compiled only**. There is no
  P2P "blocklist broadcast", no on-chain registry, no consensus mutation.
  A peer's blocklist is never applied to your node — otherwise the
  blocklist becomes a censorship oracle (a coalition excises honest keys)
  and a poison vector (spam keys fill the list, honest keys evicted).
- Updating the compiled default list is a **release-review event**, like a
  seed list change, not a network event.

**Why mining pools cannot take over attestation (layered).**

| Layer | Mechanism |
|---|---|
| Admission | Pin membership is operator ceremony only. Pools cannot add their keys. |
| Authority | Open keys ≠ `HasQuorum` (axiom). Cheap signatures cannot mint skip, work, or fork choice. |
| Equivocation | A pool key that signs two twins at one height is frozen locally (open keys; pin keys keep 0.33 dual-twin recovery). |
| Flood | Per-height and total heard-store caps prevent a key flood from owning the directory signal. |
| Audit | WindowReplay (store-only, experimental) lets clients drop keys that cannot prove the GPU ran; a pool's stolen laptop WIF fails. |
| Excision | `-matmulattestationblocklist` / `addmatmulattestationblocklist` removes a pool's keys from a client without waiting for any network process. |
| Replay scope | `replay_authority_context` binds statements to the predicate, so pool statements cannot be replayed across release/context changes. |

A blocklist is social, like every list in Bitcoin (seeds, checkpoints); it
must never be the *only* defense, which is why §1 and the axioms stay.

## 3. Global CPU-archive continuity contract (never changes)

Every phase inherits these. A CPU archive is a machine without a qualifying
GPU that runs `-matmulvalidation=trusted` (Phases 0–4) and, from Phase 5,
may run as an honestly named light client with compiled pins plus an
optional trusted fallback.

1. **Header stays 182 bytes.** No attestation bits, no proof bytes, no
   digest reseal on 0.34.
2. **`CheckBlock` never reads attestations.** Validity is ExactReplay
   (full nodes) or pin quorum (trusted archives), never signatures as
   consensus.
3. **`HasQuorum(H)` = pin M-of-N only.** Open/admitted keys never count.
   `HasQuorumLocked` = pin votes only; `IsAuthoritySigner` = pin members only.
4. **The only ExactReplay skip on an archive is**
   `trusted_mirror && pin_quorum_covers_hash`. A skip never writes
   `BLOCK_EXACT_REPLAY_VERIFIED`; `BLOCK_TRUSTED_REPLAY_ATTESTED` persists
   only on a trusted mirror with pin coverage, and startup reconciliation
   clears it otherwise.
5. **Heard never moves BestKnown, the signed frontier, or GETDATA.**
   `ShouldAdvanceBestKnownFromMmAttest` is Accepted/Duplicate only.
6. **The pin is client-local config, never P2P-mutable.** No key-join
   gossip; admission is config plus ceremony.
7. **`loadtxoutsetattested` stays trusted-mirror-only.** Consensus nodes
   use `loadtxoutset`; the UTXO pin is compiled (assumeutxo), not a live
   GPU query.
8. **P2P budgets and windows hold.** GETMMATTEST serve windows, cached
   catch-up window, hammer-ban, historical reverify budget, caps — 0.34
   must not multiply signed twins or stall 0.33.4 archives.
9. **Archives never sign.** No attestation WIF on CPU archives; never
   collocate a mining WIF with an attestation WIF.
10. **No consensus param / ASERT / F / EncDr digest change on 0.34.**
    EncDr stall recovery stays on the 0.33.4 line.

## 4. Phases

### Phase 0 — 0.33.4 stay (today)

**Goal:** nothing changes. This is the baseline contract every later phase
must preserve. Live state (2026-08-25): ExactReplay consensus authority;
closed operator pin, threshold effectively 1 with a 2-key roster; trusted
mirrors (public CPU seeds) follow the pin; assumeutxo pin at the 199299 flag day;
open speak off (`-matmulopenattestors=0`).

**Roll order:** none. No code, no config, no topology change.

**CPU-archive continuity contract — must not change:**

- trusted mode semantics and the pin path; the 1-of-1 warning stays until
  Phase 2 reconfigures the fleet;
- header, `CheckBlock`, `HasQuorum`, skip matrix, Heard rules (§3 items 1–6);
- assumeutxo / `loadtxoutsetattested` behavior (the 199299/199300 pins
  were withdrawn in 0.34.5, issue 127; remaining pin is 191266);
- GETMMATTEST windows and budgets, EncDr recovery, ASERT/F.

### Phase 1 — 0.34 local (branch soak; not a release)

**Goal:** build, unit-test, and soak the open-attestor framework on this
branch without any network roll. Deliverables: the 2×2 skip matrix test
(mirror × attestation) plus `HistoricalExactReplayCoveredByPinQuorum`;
`!ShouldAdvanceBestKnownFromMmAttest(..., Heard)`; stale docs fixed
(0.34-open-attestor-framework.md §8, `-matmulopenattestors` help); the
one-arg test compile break fixed.

**Roll order:** none to mainnet. Local testnet + trusted-mirror rehearsal
only. Gate: `test_btx --run_test=trusted_exact_replay_attestation_tests`
and `--run_test=matmul_trusted_mirror_tests` pass; no `CLIENT_VERSION` bump;
no push.

**CPU-archive continuity contract — must not change:** identical binary
behavior to Phase 0 for archives. Open speak is off by default; the trusted
skip remains the only skip; Heard (even if toggled on in a rehearsal) never
moves BestKnown; startup reconciliation still clears the persisted trusted
bit unless the node is a trusted mirror with pin quorum.

### Phase 2 — M=2 pin (gate before public miners)

**Goal:** remove the single-key archive hijack surface. Live threshold 1
means one stolen attestor WIF hijacks every trusted mirror; M=2 is the
operator gate **before** any public-miner announcement.

**Roll order:**

1. GPU attestor #2 online, still at M=1 (availability only; do not add
   authority with M=1 beyond what already exists).
2. GPU attestor #3 online.
3. All trusted mirrors/archives switch to `M=2` of the 3 keys in **one
   maintenance window**; compare `attestation_version` and
   `replay_authority_context` across the fleet first.
4. Operator configs remove the 1-of-1 startup warning; 2-of-3 preferred so
   one offline attestor does not stall archives.

**CPU-archive continuity contract — must not change:**

- still trusted mode; skip still requires `pin_quorum_covers_hash` with the
  **new** M — a misconfigured M=1 archive is a degraded light client, not
  a network hazard, but it warns loudly;
- open keys still count toward nothing (§3 items 3–5);
- no fork-choice, GBT, or header change; rotation is prospective
  (`BLOCK_VALID_SCRIPTS` chainstate is not replayed by restart);
- archives still never sign.

### Phase 3 — public miners

**Goal:** open permissionless block production. Anyone with a qualifying
GPU mines by ExactReplay; mining never depends on attestations.

**Roll order:**

1. Seeds/archives confirm M=2 and the attested chain is the
   ExactReplay-valid chain (Phase 2 soak).
2. Mining tooling: GBT on any ExactReplay-valid parent; attested tip is a
   **hint** for CPU catch-up, not a consensus parent rule.
3. Public announcement after a mining-window soak (target/GBT/twin checks).
4. Attestors **last**: they keep signing; nothing about their role changes
   yet.

**CPU-archive continuity contract — must not change:**

- archives serve miners exactly as in Phase 2; miners never require an
  attestation to produce or relay a block;
- the archive's attested tip remains hint/telemetry, never a consensus
  rule; no new skip paths;
- header, `CheckBlock`, `HasQuorum`, budgets, EncDr line unchanged.

### Phase 4 — independent GPU attestors (open speak on)

**Goal:** decentralize the *sidecar*: any GPU that ExactReplays may gossip
v2 statements; the operator is no longer the only speaker. This is Slice B
network-enabled.

**Roll order:**

1. Watchtower/refute infrastructure and the blocklist binaries first
   (`mmatrefute` pin-M veto of the open-quorum directory signal;
   `-matmulattestorblocklist`; caps; equivocation freeze).
2. Flip `-matmulopenattestors` default to 1 (opt-out) after soak; Heard
   store, directory, and `getmatmulattestors` listing go live.
3. RPC/directory exposure (`getmatmulattestors` suppression marks,
   extended `getmatmultrustedstatus`).
4. Ceremony admission of good open keys into the pin **last** and only per
   operator decision; this is how the pin set grows beyond the operator's
   own GPUs.

**CPU-archive continuity contract — must not change:**

- open keys never `HasQuorum`; Heard never moves BestKnown / signed
  frontier / GETDATA; the trusted skip remains the only skip;
- heard-store caps, equivocation freeze, and the blocklist hold on
  archives; a pool key flood changes telemetry, nothing else;
- P2P budgets/windows identical to Phase 2/3; no header or consensus
  change; `-matmulopenattestors=0` must be sufficient to restore Phase 2
  behavior exactly.

### Phase 5 — Public seeds become discovery relays (GPU attestors stay off DNS)

**Goal:** the public DNS/`addnode` layer stops being MatMul authority and
stops fanning `GETMMATTEST` into GPU attestors. Archives follow the chain
GPU nodes attest. Relays only introduce peers. Permissionless GPU miners
ExactReplay; they are not the seed oracle.

This **replaces** the earlier “convert every public seed to a GPU full
node” plan. Putting ExactReplay on the DNS hosts would keep those IPs as
chain oracles and keep load on the same machines. Discovery relays are
not oracles.

**Roll order:**

1. One public seed converts: `-matmulvalidation=relay`, `-disablewallet=1`,
   drop pin / `GETMMATTEST` serve / `NODE_NETWORK`. Confirm
   `getnetworkinfo.localservicesnames` includes `MATMUL_DISCOVERY` and not
   `NETWORK` / `MATMUL_TRUSTED_MIRROR` / `MATMUL_ATTESTATION_ARCHIVE`. Soak.
2. Next seed, one at a time; never flip the public introduction layer in
   one window.
3. GPU attestors stay `-discover=0` and out of DNS/`addnode`. Archives
   remain `trusted` + pin and are the IBD / attestation-cache layer.
4. Emergency-override mechanics (below) stay on archives, not relays.
5. Residual CPU archives are relabeled **honestly named light clients**
   (weak subjectivity + compiled pins) in operator docs and
   `getmatmultrustedstatus`.

**CPU-archive continuity contract — must not change:**

- the residual archives' contract is now: compiled pins for history
  (assumeutxo 191266 + default assumevalid + `nMinimumChainWork`; the
  199299/199300 pins were withdrawn in 0.34.5, issue 127), live pin
  for the tip, and the emergency override — **no new consensus**;
- `loadtxoutset` stays the UTXO pin; `loadtxoutsetattested` remains
  trusted-mirror-only and is never a consensus path;
- archives still never ExactReplay, never sign, never claim full-node
  status; no SNARK/STARK/FlyClient claim (Epoch C only);
- discovery relays never skip ExactReplay, never ConnectTip Profile-1 as
  valid, never request `GETMMATTEST`; F / ASERT / digest untouched.

### Phase 6 — Epoch C (proof authority; later height)

**Goal:** succinct proofs make attestors fully optional; phones and CPU
clients verify a proof, not a key. **Separately reviewed activation height.
Not 0.34. No proof ships in 0.34.**

**Roll order (Epoch C proper):** research + external adversarial review of
the proof and its header projection → testnet proof soak → exact-final
budget freeze → activation-height review with a live-tip runway (same
discipline as the v4.7 Epoch-A tuple) → activation.

**CPU-archive continuity contract — must not change until Epoch C
activates:** ExactReplay remains consensus authority; the pin remains the
archive contract; no proof bytes in the 182-byte header; no attestation
bits in `CheckBlock`; open keys never `HasQuorum`. At activation, attestors
become vestigial for light clients; the pin degrades to compiled history
plus emergency override.

|---|---|---|---|
| 0 — 0.33.4 stay | — | — | baseline (§3) |
| 1 — 0.34 local | no network roll | no network roll | identical binary behavior |
| 2 — M=2 | attestor #2, #3 GPUs | mirrors switch to M=2 | trusted mode, skip matrix |
| 3 — public miners | seeds confirm M=2 | attestors keep signing | mining independent of attestation |

## 6. How operator attestors become optional + emergency hijack

**Decay path (each step is a config/topology change, never a consensus
change):**

| Phase | Attestor role | What CPU archives need |
|---|---|---|
| 0–1 | Daily authority (closed pin, T=1) | pin for everything (weak subjectivity) |
| 2 | Shared authority, M=2-of-3 | pin; no single attestor is required to be online |
| 3 | Still authority for archives; irrelevant to miners | pin; mining is already independent |
| 4 | One speaker among many; open directory | pin; heard statements are telemetry |
| 5 | Optional; residual archives keep pinned fallback | compiled pins + live pin + emergency override |
| 6 (Epoch C) | Vestigial / fully optional | proofs; pin = compiled history only |

"Stop needing to run operator attestors forever" therefore means: the
operator's GPUs are **retired box-by-box from Phase 5**, and the last
operator attestor can go dark once (a) no trusted mirror depends on it and
(b) Epoch C or a client-owned GPU covers the residual need. Nothing in this
decay ever makes an open key an authority — that is the whole point.

**Emergency hijack override (the only "auto" that is allowed to be manual).**

- Semantics: a documented, **manual** operator override on a trusted mirror
  or light client (e.g. freeze at a pinned hash, or fail-safe to a compiled
  pin) for one of: confirmed pin WIF compromise, catastrophic ExactReplay
  regression, or a coordinated attack on the attested chain.
- Properties: must be explicitly asserted per incident; **expires** (must be
  re-asserted); is rate-limited; logs at ERROR; and is surfaced in
  `getmatmultrustedstatus` on every mirror that follows it. It is never
  derived from observed gossip, never default, never silent.
- The normal case is the inverse: archives follow the chain their pin
  attests, the pin tracks the ExactReplay-verified network, and the override
  is the exception that watchtowers/refutations + logs make visible.

## 7. Phase gates (verification)

- **Phase 1:** `trusted_exact_replay_attestation_tests`,
  `matmul_trusted_mirror_tests`, new Heard/BestKnown and 2×2 skip cases,
  full unit suite in `build-gcc13`; docs consistent (this study, gold doc,
  open-attestor framework, mirrors, init help).
- **Phase 2:** fleet-wide `replay_authority_context` equality before the
  M=2 window; mirror tip-lag and quorum-timeout alerts green.
- **Phase 3:** mining soak with no attested-tip requirement; twin/
  HeightOccupied checks on collocated miner+signer configs (still
  prohibited).
- **Phase 4:** caps/equivocation/blocklist soak with adversarial key floods
  (the heard-store must not grow, BestKnown must not move, skip must not
  appear).
- **Phase 5:** one public DNS host at a time to `-matmulvalidation=relay`;
  confirm it no longer requests GETMMATTEST and no longer advertises
  NODE_NETWORK / NODE_MATMUL_TRUSTED_MIRROR before converting the next.
- **Phase 6:** per the v4.7 roadmap proof-security gates; nothing here.

## 8. Axioms this document does not change

1. Open attestor keys are not `HasQuorum`.
2. Consensus miners ExactReplay; the pin skip is trusted-mirror only.
3. Heard is not BestKnown; Heard never moves signed frontier or GETDATA.
4. No SNARK/STARK/FlyClient/NIPoPoW as 0.34 consensus; Epoch C stays a
   later height.
5. No consensus param / ASERT / F / EncDr digest reseal on this branch.
6. No `CLIENT_VERSION` 0.34, no push, no live GPU-attestor restart.
