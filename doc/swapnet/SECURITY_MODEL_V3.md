# Security model and assurance boundaries

## Principals

Only native authenticated RPC contexts create owner authority. Peer JSON cannot assert owner, select wallet, set verifier endpoints or call arbitrary native RPC. Restricted RPCAUTH users stay restricted. ModelNet admission and IPC bearer credentials never grant monetary signing authority.

## Economic promises

A signature authenticates explicit terms, not a fair price, collateral, reserves or independent business ownership. A local firm offer prevents the honest implementation from double-allocating its tracked inventory/mandate capacity, but cannot constrain funds spent outside that implementation. All actual swaps still require exact independently observed HTLC locks and safe staggered deadlines.

The design addresses privileged custody, private-ledger delivery opacity and mandatory admission control. It does not prohibit voluntary sales, outside accumulation, coordinated prices or unattractive disclosed spreads. No allegation about a named third party is certified by this software.

## Recovery

Mode changes and new-trade policies must not block authorized recovery. No cache or advertisement can authorize a fresh funding transaction after journal restoration. A local timeout is not an absence proof. Existing original-transaction reconciliation and immutable operation-WAL behavior are retained. Schema downgrade refuses instead of ignoring new capacity obligations.

## Public data and privacy

Only maker-selected public offer data is gossiped. User balances, private keys, preimages, recovery passphrases and raw signed claim transactions are never published. Directed RFQs reduce broad disclosure but relays may observe them. Receipts are local/voluntary exports; a signed observation is not automatically an independently verified on-chain outcome. EVM pull-payment credits require separate payout reconciliation.

## Invitation safety

Inspection is inert; connection is owner-reviewed. A peer link is not a verifier configuration or payment request. Explicit DNS/private-network exceptions must be visible. Native onlynet/proxy/banning policies continue to apply. A link cannot guarantee internet reachability or authenticate a provider merely through TCP.

## Platform limits

Portable source is not evidence of a native platform build. This package's QA register must identify exact commands, source identities, return codes, failures and unrun gates. A security review, funded native lifecycle, Windows/macOS release, and OS URI registration each require their own evidence. Never substitute old binaries or simulated chain drivers for a successful candidate-native test.
