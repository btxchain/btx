# BTX 0.35.0rc1 release-candidate checklist

This is the checklist for the prerelease tag `v0.35.0-rc1`. It is not a
qualification record. `ReleaseGate` is not complete, and there is no final
`v0.35.0` tag.

The binaries were built from commit `849fb2d84ec9f5f02acd9d2a84f9272fd02f8a3e`.
`btxd -version` reports `v0.35.0rc1`.

## How CUDA gets into a binary

CUDA is not compiled into every build. CMake turns on
`BTX_ENABLE_CUDA_EXPERIMENTAL` only when it finds a CUDA compiler, unless the
configure line forces it on. Forcing it on with no compiler fails configure.
A binary with the option off still contains the text of the CUDA stubs. Those
strings are not a CUDA backend.

A native CUDA run is not required to answer whether the backend was compiled.
The import table and `btx-matmul-backend-info` answer that.

## What this tree runs

Archive rows above record the `v0.35.0-rc1` packages built from `849fb2d84ec9f5f02acd9d2a84f9272fd02f8a3e`. This section records the swarm observer in this tree. An archive box is a package check. It does not set the swarm release flags below.

`btxd` starts `StartSwarmObserver` in-process after the model helper. The branch includes the 0.35 lab tip through merge commit `ee9648fd` on top of `b35d1b9d`.

- [x] In-process bind suites on `b35d1b9d`: 14 cases, exit 0. Process-local.
- [x] Earlier journal and requirement suites on `56f00405`: 62 cases, exit 0. Process-local.

The live pass is latched: an 8-byte memory echo of `abcdefgh`, vllm `ENGINE_ABSENT`, one CPU AdamW step, a one-host two-rank loopback exchange, 8 integer replay pairs, one snapshot, one realm seat, then the requirement and cycle checks. Spend is `0`. Release is `UNQUALIFIED`. `passed()`, `gpu_passed()`, and `windows_passed()` stay false.

A one-GPU two-process script on one machine has exchanged two ranks and reported `RELEASE_QUALIFIED 0`. That run is one machine. A release requires two hosts, so the release stays `UNQUALIFIED`.

## Later releases

Later releases move toward a fully autonomous network. Each row stays open until the verification named on it has been completed.

- [ ] Peer discovery and local admission: two physical hosts, with every privileged peer absent
- [ ] Acquiring a verified model from another participant: a signed artifact moving between two processes that are not the same snapshot object
- [ ] A submitted task or prompt returning model work: a user-supplied prompt on a linked execution engine. The fixed internal text `abcdefgh` is the latched echo and does not meet this row
- [ ] Authorized training checked by a second machine: a second physical host and, for a GPU claim, a second GPU. One device and two ranks do not qualify
- [ ] A private defensive case: an explicit customer grant. Private prompts stay off until that grant exists
- [ ] Settlement: an operator-signed mandate and an isolated-regtest payment. Until then spend stays `0`
- [ ] Windows, macOS, an offline release image, the hardware profiles, and the sealed acceptance catalogue stay unverified
