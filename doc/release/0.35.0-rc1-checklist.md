# BTX 0.35.0rc1 release-candidate checklist

This is the checklist for the prerelease tag `v0.35.0-rc1`. It is not a
qualification record. `ReleaseGate` is not complete, and there is no final
`v0.35.0` tag.

The binaries were built from commit `849fb2d84ec9f5f02acd9d2a84f9272fd02f8a3e`.
`btxd -version` reports `v0.35.0rc1`.

## How CUDA gets into a binary

CUDA is not compiled into every build. CMake turns on
`BTX_ENABLE_CUDA_EXPERIMENTAL` only when it finds a CUDA compiler, unless the
configure line forces it on. Forcing it on with no compiler fails configure.
A binary with the option off still contains the text of the CUDA stubs. Those
strings are not a CUDA backend.

A native CUDA run is not required to answer whether the backend was compiled.
The import table and `btx-matmul-backend-info` answer that.

## Candidate archives

| Archive | GUI | ZeroMQ | Device backend | Launch notes |
| --- | --- | --- | --- | --- |
| Linux x86_64 | on, Qt 6 copied into `lib/` | system `libzmq.so.5` | CUDA compiled **off** | `verify_release_btxd.py` PASS, including `btxd -version` |
| macOS arm64 | on, Qt 6 inside `btx-qt.app` | static | Metal compiled **on**, kernels in `bin/metal/` | static ZeroMQ check PASS; the GUI printed `v0.35.0rc1` |

`scripts/release/verify_release_btxd.py` checks ZeroMQ linkage and, on Linux,
that `btxd -version` exits 0. It does not check CUDA.

### Linux x86_64

- [x] `bin/btxd`, `bin/btx-qt`, `bin/btx-cli`, `bin/btx-tx`, `bin/btx-util`, `bin/btx-wallet`
- [x] `btxd -version` prints `v0.35.0rc1`
- [x] `btxd` links `libzmq.so.5`
- [x] `btx-qt` loads Qt 6 from `lib/` beside `bin/` (`libQt6Widgets`, `libQt6Gui`, `libQt6Network`, `libQt6DBus`, `libQt6Core`) and the `xcb` platform plugin from `lib/qt6/plugins/platforms/`
- [x] No `libcudart`, `libcublasLt`, or `libcuda` in the dynamic table
- [x] `btx-matmul-backend-info` reports `cuda.compiled=false`, reason `disabled_by_build`
- [ ] CUDA MatMul backend. No CUDA compiler was present at configure, so this archive cannot GPU-mine
- [x] GLIBC floor recorded: `GLIBC_2.38`, `GLIBCXX_3.4.32`, `CXXABI_1.3.15`. Older C libraries will not start it
- [x] OpenSSL floor recorded next to that: `OPENSSL_3.2.0` (OpenSSL >= 3.2). Ubuntu 24.04's system `libssl.so.3` does not provide that version node. The archive ships `lib/libssl.so.3`. `btxd`, `btx-cli`, `btx-tx`, `btx-util`, `btx-wallet`, and the model tools need link-time `RUNPATH` `$ORIGIN/../lib` (the same relative path `btx-qt` already uses) so the loader opens the packaged library. The reviewed rc1 `btxd` had no `RUNPATH`
- [x] `verify_release_btxd.py --archive` PASS

### macOS arm64

- [x] `bin/btxd` links the system Metal framework and static ZeroMQ
- [x] Nine Metal kernels are in `bin/metal/` next to `btxd`
- [x] `btx-qt.app` contains Qt 6. The GUI's load commands point at `@executable_path/../Frameworks`, not a Homebrew library path
- [x] `btx-qt.app` printed `BTX version v0.35.0rc1`
- [x] `verify_release_btxd.py --archive` PASS for static ZeroMQ. Launch of the Mach-O was skipped on the non-Mac gate host
- [ ] On a Mac: `codesign --verify --strict` on every Mach-O in the archive, then `btxd -version`. This candidate was not checked that way
- [ ] Metallib paths must be final before `codesign`. CMake bakes `BTX_*_METALLIB_PATH` at configure time (absolute build-tree paths today) and the runtime also looks in `<directory of btxd>/metal/<name>.metallib`. Set the packaged location at configure or generate time. Do not rewrite those strings inside `btxd` after `codesign`; the release packager only copies `.metallib` files and does not patch the Mach-O
- [ ] Some Qt install ids still name the Qt prefix used at build time. Startup uses the copies inside the app
- [ ] Ad-hoc signature only. No Developer ID signature
- CUDA is not the macOS device backend. Metal is

### Windows x86_64

- [x] `btxd.exe`, `btx-qt.exe`, `btx-cli.exe`, `btx-tx.exe`, `btx-util.exe`, `btx-wallet.exe`
- [x] Version resource and version string `v0.35.0rc1`
- [x] `btx-qt.exe` is a GUI PE. Qt 5 is static. No Qt DLL is imported
- [x] ZeroMQ is static. The daemon contains `ZeroMQ notification options`
- [x] `libgomp-1.dll`, `libgcc_s_seh-1.dll`, and `libwinpthread-1.dll` sit next to the executables. Without them the loader cannot start `btxd.exe`
- [x] Import table has no `nvcuda.dll`, `cudart`, or `cublas`
- [x] The image contains `RC Ozaki CUDA ExactPanels TU not linked (BTX_ENABLE_CUDA_EXPERIMENTAL off)` and `disabled_by_build`
- [ ] CUDA MatMul backend. This MinGW cross compile had no CUDA compiler. The Linux CUDA compiler does not emit this Windows binary. A Windows CUDA toolkit is required before this archive can GPU-mine
- [x] `verify_release_btxd.py --archive` PASS. The PE was not launched on the build host
- A native CUDA execution test was not required. The missing piece is the compile, not that test
