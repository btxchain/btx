# What the 0.35 lab slices do

This note describes the code on `btx-035/lab` after the release candidate. It is not a qualification record. The sealed acceptance catalogue stays `NOT_RUN`. Windows and macOS have not run these journeys. There is no final `v0.35.0` tag.

## A second node can verify a snapshot

`lab.git_snapshot` stores the commit bytes and their SHA-384 Git object digest. `lab.snapshot_export` writes a manifest of those objects. `lab.snapshot_import` checks every digest against the bytes and rejects a replaced blob. `lab.snapshot_pull` fetches that manifest from another node over JSON-RPC. The peer host must be `127.0.0.1`. A public address is refused.

`lab.git_fetch_ticket` returns a random 64-hex bearer for that repository. It does not invent a socket. The bearer is presented as `fetch_ticket` on `lab.snapshot_export`. A second use is `BTX035_REPLAY`. A payload larger than the ticket's `max_bytes` is `BTX035_POLICY`. `lab.source_query` searches the retained object bytes and returns matching digests. `lab.artifact_acquire` copies one of those objects when the digest is present and within `max_bytes`; otherwise the operation is `FAILED` and `STOPPED_QUIESCENT`. `lab.migration_apply` completes only when `plan_ref.digest48` is a plan `lab.migration_plan` stored.

## Research views

`lab.research_publish` keeps the row, including a negative result and a private row. `lab.research_frontier` sorts the retained rows for `LEADING`, `CONTESTED`, `NEGLECTED`, `RECENT`, or `REPRODUCED`. A public query omits private rows. Nothing in this path assigns an experiment to an author.

## Integer training and replay

`INTEGER_LINEAR` is a deterministic trainer with integer weights, momentum, and a frozen eight-row dataset. It is separate from the four-byte `EXACT_CHECKS` fixture. `lab.research_execute` runs it when the recipe id is `INTEGER_LINEAR` and a local grant exists. `lab.audit_coverage` replays the stored state. A changed cursor is `BTX035_RNG`. A changed weight is `BTX035_ID_MISMATCH`. Resume from step zero is `BTX035_NOT_RESUMABLE`.

`lab.admission_evaluate` admits only when those stored trajectories pass the strict admission check: matching state, full coverage, and independent authors. A hash match by itself is not enough.

## One admission gate on the live paths

`LivePathAllowed` is the same decision as serve and generate. Publishing an import, seeding, demand-seed, loading, and generating all call it before they activate a model. An id that was never registered, and is not quarantined, stays servable.

## A guard process

`btx-guardd --stdio` uses private inherited IPC and is the default observer-owned process; it opens no TCP listener. The explicit legacy diagnostic command `btx-guardd --port <port> --allow-legacy-loopback` listens on `127.0.0.1` and issues a random one-use permit that expires in 30 seconds. A successful consume returns `PERMIT_CONSUMED NOT_DISPATCHED`, not a claim of model execution. A second consume is `BTX035_REPLAY`. Pause revokes outstanding permits and blocks a new permit; resume requires a fresh permit. A wallet or spend effect is refused. `lab.action_prepare` uses the same table inside the node and returns the bearer as `one_use_permit`. The stored record id is the commitment, not the bearer. `lab.runtime_pause` pauses that table as well as the action gate, so an unused permit is not consumed while the runtime is paused. A protected assurance (`SOFTWARE_ISOLATED`, `VM_ISOLATED`, `HARDWARE_ATTESTED`) is refused unless `BTX_GUARD_PORT` is set, so the node does not pretend a separate guard is present.

## What is still not a qualified release

Release archives keep shared libraries in `lib/` and give the `bin/` tools link-time `RUNPATH` `$ORIGIN/../lib`. Metal `.metallib` paths must be final at configure time, before `codesign`.

`modelnet_035_complete_tests` covers the integer replay, the research views, the exchange mismatch, and the one-use permit. `contrib/modelnet/lab035_independent_source.py` starts two regtest nodes: the second pulls the snapshot over JSON-RPC after the origin directory is gone, and a replaced blob is `BTX035_ID_MISMATCH`. That script has been run on Linux. It is not the seven-process WAN journey, and it has not been run on Windows or macOS. The sealed acceptance catalogue stays `NOT_RUN`. There is no production signature and no final `v0.35.0` tag. Without `BTX035_LAB_DIR`, the lab RPC store is process memory. Setting `BTX035_LAB_DIR` enables the lab disk image and piece store for retained research state. Use a dedicated absolute local path. Research secret keys and one-use action permits remain process-local; disk persistence does not make them recoverable or turn these tests into release qualification.

## Later releases

Later releases move toward a fully autonomous network. Each claim waits for the verification named with it.

- Peer discovery and local admission require two physical hosts, with every privileged peer absent.
- Acquiring a verified model from another participant requires a signed artifact moving between two processes that are not the same snapshot object.
- A submitted task or prompt returning model work requires a user-supplied prompt on a linked execution engine. The latched echo is the fixed internal text `abcdefgh`, and that text does not meet this claim.
- Authorized training checked by a second machine requires a second physical host and, for a GPU claim, a second GPU. One device and two ranks do not qualify.
- A private defensive case requires an explicit customer grant. Private prompts stay off until that grant exists.
- Settlement requires an operator-signed mandate and an isolated-regtest payment. Until then spend stays `0`.
- Windows, macOS, an offline release image, the hardware profiles, and the sealed acceptance catalogue stay unverified.
