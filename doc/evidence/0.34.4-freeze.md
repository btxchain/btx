# 0.34.4 golden freeze

This commit is the freeze `F` for v0.34.4. It bumps
`CLIENT_VERSION_BUILD` to 4. Parent is `f064eabc` (0.34.3 merge; seal
`099ae7ea` is an ancestor). BUILD_RELEVANT relative to the 0.34.3 seal:
`src/net_processing.cpp`, `src/node/header_sync.h`, `src/node/chainstate.cpp`,
`src/validation.cpp`, `src/validation.h`, `CMakeLists.txt`, and the matching
unit tests. The golden manifest must be remeasured.

This freeze lands the headers-below-blocks catch-up fix. Live 0.34.3 on
<node>: `blocks=199310`, `headers=199024` (`m_best_header` 286 below the
connected tip). `PreferTrustAdjustedHeader` ranked the last fully-authenticated
ancestor above a long unauthenticated suffix. getheaders locators started at
199023; the only peer advertising above us (`<operator-node>` /BTX:0.34.2/
`startingheight=199399`) answered from the 0.34.1 fork (`33c834f8`) in a hot
loop. Majority peers advertised 199294–199310 at VERSION time and were never
probed. Zero `Saw new header`, zero getdata.

`EnsureBestHeaderNotBehindConnectedTip` snaps `m_best_header` up to
`ActiveTip` when it sits strictly below the connected chain. Locators use
`HeaderSyncLocatorStart` (tip, not a behind ancestor). `HeaderSyncMustProbe`
still asks when BestKnown is pinned at our height, and when the tip is stale
even if VERSION advertised below us. Cached-invalid / duplicate-ancestor
batches restamp the 2-minute getheaders gate so we cannot hot-loop the fork.

Regressions:
- `header_sync_tests` (locator start + must-probe table)
- `peerman_tests/best_header_below_tip_rerequests_headers_and_converges`

Do not invert `prefer_trust_adjusted_header_chooses_shallow_capped_tip`:
anti-flood ranking stays; this freeze only floors the download locator.
